# 아키텍처 상세 (모듈 단위 규칙의 원문)

CLAUDE.md 의 "아키텍처 핵심 규칙" 에서 옮겨 온 모듈 단위 상세다. CLAUDE.md 에는 요약과 이 문서로의 포인터만 남긴다(세션 컨텍스트 절약). **코드가 출처**라 함수 시그니처·상수가 어긋나면 이 문서를 고친다. Phase 완료 시점에 CLAUDE.md 와 함께 대조한다.

## scan(스펙 §5.1)

**scan(스펙 §5.1).** `scan/quant.score` 는 피처 스토어 최신 행으로 거래대금 하위 30%·변동성 상위 10% 제외 후 z(roc_10)·0.5 + z(52주 위치)·0.3 + z(log 거래대금)·0.2, 상한 30. `rank_fn` 훅이 ML 랭킹 자리(Phase 7). screener 세션은 `SessionSpec(kind="screen", candidates=…)` 로 `--agents` 에 screener 만 싣고 `tool submit-screen` 으로 `_screen.json`(Screened, picks 1~5)을 받는다. 세션 상한이면 정량 상위 3개. 분석 대상 = picks + 보유종목 + watch.

## 종목 발굴(Phase 19, `scan/discovery.py`)

**종목 발굴(Phase 19).** "맨 처음 종목 선정" 을 정량 필터만이 아니라 에이전트가 뉴스로 한다. screen 세션(`kind="screen"`, `SCREEN_AGENTS=("scout","screener")`) 안의 두 단계: ① 파이썬이 세션 앞에서 `_discovery_inputs`(유니버스 + 이름·섹터, 뉴스 저장소 최근 48h ≤60건(태그 포함), `_market_<시장>.md` 메모, 국면, 보유, 최근 5운영일 picks·발굴, 정량 후보 상위 30, `max_listed`)를 `market_dir` 에 쓰고(`discovery.build_inputs`, `run_screen(discovery=True)`), 오케스트레이터가 `tool scan discovery-inputs` → `scout`(sonnet, `Discovered{candidates ≤8 {name, ticker|null, market, tier universe|listed, catalyst ≤200, source_ids, confidence}, notes}`) → `tool submit-discovery`. ② `submit-discovery` 가 **코드를 확정**한다(`discovery.resolve`): 유니버스 종목은 코드 일치 또는 캐시 이름(`names.load_cache_names`, DART corpCode·EDGAR 티커 표) 정규화 일치(`normalize`: 공백·㈜·(주)·Inc/Corp/Co/Ltd 제거), 유니버스 밖은 캐시 역색인으로 코드를 찾고 KR 은 `get_price_kr` 1회(클라이언트 없으면 캐시 일치만), US 는 NAS→NYS→AMS 시세로 거래소를 확정(없으면 `unresolved`), 헤지 ETF·`universe.exclude`·보유 종목은 제외, 유니버스 밖은 `MAX_LISTED`(2) 까지. 결과 `_discovery`(+`unresolved`) 와 **병합 후보**(`discovery.merge`: 유니버스∧발굴(점수순, reasons 에 "뉴스 발굴: …") → 유니버스 밖 발굴(score None, 확신순) → 나머지 정량)를 돌려주고 screener 가 이것을 받는다(screener.md: `discovery.tier == "listed"` 는 score 없이도 picks 가능 ≤2, 유니버스 발굴은 촉매가 구체적이면 우선). 분석 대상의 거래소는 잔고 → 후보 → `_discovery` → universe.us 순. `_scan.json.discovery` 요약(`discovery.summary/line`: "뉴스 발굴 n(유니버스 k·밖 m·미해결 u)"). 세션 수는 늘지 않고(세션 1회 안의 단계) 발굴 입력 실패·도구 거부는 발굴 없이 스크리닝으로 떨어진다. `FAKE_CLAUDE=1` 은 정량 점수 순 첫 유니버스 종목 1개를 발굴로 흉내 낸다. 유니버스 밖 종목은 피처·섹터가 없어 `05_quant` 없음·섹터 `기타` 로 분석된다.

## 뉴스 저장소(Phase 19, `sources/news_store.py`)

**뉴스 저장소(Phase 19).** 종목이 정해진 뒤 종목별로만 뉴스를 받던 구조로는 발굴이 불가능하므로 **시장 전체 뉴스**를 상시 저장한다. 원장 v14 `news_items(market, source, query, title, url, url_hash UNIQUE, published_at, received_at, summary, tickers_json, lang)`; 데몬 interval 잡 `news_collect`(`schedule.yaml news_collect.interval_s` 기본 1800, heavy 락 밖, 작업 대기열 kind `news_collect` 로 즉시 수집)가 시장별 질의 묶음(`sources.yaml news.market_queries`, KR 7·US 5 기본값, 사용자가 고친다)을 구글뉴스 RSS(+KR 네이버 뉴스)로 돌려 URL 해시로 멱등 적재(`insert_items`, 소스·질의 실패 격리)하고 `store_retention_days`(14) 지난 행을 지운다. 태깅(`tag`)은 **유니버스 종목명·코드만**(ASCII 티커는 단어 경계, 2자 미만 무시) — 유니버스 밖은 scout 의 몫. 룩어헤드: 읽기 `recent(asof, hours, limit, ticker=)` 가 `COALESCE(published_at, received_at) <= asof AND received_at <= asof`. 읽는 곳 셋 — 발굴 입력, 시장 세션 `macro_news`(저장소 우선, 태그 종목 포함, 없으면 구글 질의 1회 폴백), 종목 세션 `news.stock`(`InputDeps.conn_factory` 로 그 종목 태그 항목을 합침, URL 중복 제거, `sources.store`). 웹 `GET /api/news?market=&hours=&limit=&ticker=`(토큰 없음) + 데이터 페이지 '시장 뉴스' 표('지금 수집' 버튼). `url_hash` 는 시장 범위(`sha1("<market>|<url>")`)라 티커 없는 거시 뉴스는 KR·US 두 행이 된다.

**세이브티커 로컬 폴더(`sources/saveticker.py`).** 사이트는 긁지 않고(Cloudflare 403·robots) 사용자의 별도 수집기가 **이 프로젝트의 `state/external/saveticker/`**(`sources.yaml news.saveticker_dir`, 상대 경로는 프로젝트 루트 기준, 없으면 조용히 건너뜀)에 쌓는 파일만 읽는다. 구조(수집기 schema_version 1): `data/<YYYY-MM-DD>/{news,community,market,calendar}.jsonl`(한 줄 = `{revision, stream, received_at, item, view}`), `data/latest/<stream>.json`(`{observed_at, status, items}`), `data/attachments/<sha>.pdf|.txt`(SAVE 데일리 리포트). 뉴스(`news_all`·`news_reports`)는 `news_collect` 잡이 `ingest_news` 로 최근 3일(+내일 폴더, 시계 차) jsonl 의 마지막 revision 을 `news_items(source='saveticker:<출처>', query=<stream>)` 에 멱등 적재한다 — 시장은 티커로(6자리 → KR, 영문 → US, 없으면 둘 다), `published_at` 은 UTC 값 → 화면 시각 '2026. 10. 24. 07:40'(KST) → 없으면 None(상대시각), 리포트는 `report_date` 08:00 KST 와 추출 텍스트 발췌(300자), URL 은 `source_url` 또는 합성(`#<id>`·`#report-<date>`), 수집기 티커는 `insert_items(extra_tickers=True)` 로 태그와 합친다. 화면 스냅샷 `snapshot(root, asof)` 는 `observed_at <= asof` 인 latest 만 읽어 `{trends, index, community_top5, community{gain,loss}, movers{gain,loss,turnover}(정규장 기준), calendar(asof −1~+7일), report{report_date, excerpt ≤1500}, streams_status}` 를 만들고 — 종목 세션 `sentiment.saveticker`(`for_ticker`: 이 종목이 등장하는 행 `mentions` + `trends`·`index`, 폴더 없으면 `no saveticker dir` 건너뜀), 시장 세션 `_market_inputs.saveticker`(캘린더가 7일 일정의 1차 출처), 발굴 입력 `saveticker`(trends·movers·top5·report; scout.md 는 "상위 노출은 결과, 촉매 아님")에 들어간다. 애널리스트 md(`analyst-sentiment`·`analyst-news-macro`·`analyst-market`·`scout`)가 절 이름과 한계를 안다.

## 전략가 지표(Phase 19, `risk/regime.py`·`orchestrator/hedge.py`)

**전략가 지표(Phase 19).** 시장 세션 제안이 비중만 조절하던 것을 국면 판정에도 넣는다 — 단 파이썬 규칙 안에서. `RegimeSignals.agent_risk_off` 가 4번째 지표로 `count` 에 +1 하되 `raw_state` 는 정량 지표 0개면 전략가만으로 neutral 까지만 올린다(bear 진입은 지표 1개 이상 + 전략가). 데몬 `_scan_analyze_body` 순서는 `_regime_body → _market_view_body → _regime_apply_view → scan → analyze`: 오늘 제안이 RISK_OFF 이고 `confidence ≥ hedge.agent_min_confidence`(0.7) 면 `regime.reapply(agent_risk_off=True)` 로 저장된 오늘 지표에 신호만 바꿔 재판정(같은 운영일 재계산이라 streak 겹침 없음, 전환은 `[국면 전환] … (1/3+전략가)` 알림), 아니면 신호를 끈 채 재판정(어제 신호가 남지 않게). `hedge.agent_signal=false` 면 전부 꺼진다. **RISK_ON 하루 보류**: `hedge.rebalance` 가 bear 진입 직전에 `_risk_on_deferral` — 제안 RISK_ON ∧ 확신 ≥ 기준 ∧ 정량 지표 수 == `bear_min_signals`(경계) ∧ 3/3 아님이면 `action: deferred` 로 그날 플래그를 세우고(알림 1건) 진입하지 않는다; 3/3·확신 낮음·해제는 영향 없다. 가시성은 `regime.count_text`(STATUS·텔레그램·알림)·웹 `countText`·지표 라벨 '전략가 위험 회피'. 평가는 기존 scorecard(제안 적중률)로 2~4주 뒤 — 나쁘면 `hedge.agent_signal: false`. **2026-10-26 전체 검토 L8: 기본값을 false 로 내렸다** — Phase 22 한도 기울기(`agent_gate`)가 같은 제안을 한 번 더 반영해 RISK_OFF 하나가 국면 지표 +1 과 한도 축소로 이중 작동했다. 전략가는 기울기로만 주문 범위에 닿고, 켜면 위 동작이 돌아온다.

## 응답없음 대응(Phase 20, `platform/tray.py`·`orchestrator/session.py`·`web/src/events.ts`)

**응답없음 대응(Phase 20).** 사용자 보고 "프로그램이 가끔 응답없음" 의 원인 다섯과 수정. ① 트레이 '종료' 가 메인 스레드에서 `shutdown(wait=True)` 로 실행 중 세션(≤600s)을 기다려 AppKit 런루프가 멈춤(비치볼) → `TrayController.quit_action` 은 워커 스레드로 종료를 시작하고 제목을 '종료 중' 으로 바꾼 뒤 끝나면 `icon.stop()`; `session.run_claude(cancel=stop_event)` 가 1초 폴링으로 종료 요청을 보고 프로세스 그룹 SIGTERM → `TERM_GRACE_S`(10) → SIGKILL → 파이프 drain(`SessionCancelled`), 데몬 수집 루프·`_scan_body`·`_market_view_body`·reflect 도 `stop_event` 를 본다. ② 트레이 메뉴 라벨·checked 가 호출마다 SQLite 를 열던 것 → 리프레시 스레드(30초)가 갱신하는 캐시 `TrayController.state` 만 읽고 토글은 워커. ③ 백그라운드 스레드의 AppKit 호출(`icon.title=`·`stop`) → `tray.on_main`(darwin 은 `AppHelper.callAfter`, 그 외 직접). ④ 탭마다 SSE 1개 + 브라우저 호스트당 연결 6개 한도 → 모든 fetch 가 영원히 pending(웹 '멈춤') → `events.createEventsClient`: localStorage 하트비트(2초, 6초 stale)로 리더 탭 하나만 `EventSource` 를 열고 `BroadcastChannel("trader-events")` 로 스냅샷을 중계, 리더가 닫히면(`leader-gone`) 또는 하트비트가 멈추면 승계, BroadcastChannel 이 없으면 탭마다 직접. ⑤ 데몬 스레드 사망·웹 포트 점유를 트레이가 모름 → 리프레시 루프가 `finished` 를 보고 제목 '데몬 중단' 뒤 아이콘 정지, `_start_web` 실패는 로그 + 알림. 보조: KIS 레이트리미터 `max_wait`(웹 차트·잔고 새로고침은 2초 넘으면 503 "KIS 바쁨"), YouTube 자막 15초·수집 절 180초 타임아웃, 스케줄러 풀 16. 재현 로그: `state/logs/trader*.log` 의 시그널·세션 타임아웃·database is locked·KIS 초당 한도, `~/Library/Logs/DiagnosticReports/TraderApp*.hang`.

## 전체 리뷰 수정(Phase 20, 2026-10-25)

## 전략가 기울기 게이트(Phase 22, `risk/stance.py`·`risk/rules.py`·`orchestrator/executor.py`)

**전략가 기울기 게이트(Phase 22).** "주문 허용 범위는 파이썬만 정한다" 를 한 칸 열어 에이전트(시장 세션 전략가)의 톤이 한도에 닿게 했다. `executor.execute` 가 시장·날짜마다 `_agent_tilt`(= `stance.tilt_of(market_view_today(...), min_confidence=hedge.agent_min_confidence)`) 를 한 번 구해 `rules.evaluate(agent_tilt=)` 로 넘기고, `stance.limits_for_regime(regime, limits, tilt)` 가 국면 한도를 **한 칸만** 옮긴다: bull−1 → neutral 한도(15%·3), neutral+1 → `TILT_UP`(20%·4), neutral−1 → `TILT_DOWN`(10%·2), bear+1 → 10%·2 — bear 의 신규 매수 거부 규칙은 `tilt > 0` 일 때만 "조건부 허용" 사유로 바뀐다. 설정 `risk.max_position_pct/max_positions` 보다 넓어지지 않는다(min). 헤지(`is_hedge`)·손절(`is_stop_loss`)은 tilt 0 으로 고정. 판정 reasons 에 "국면 neutral + 전략가 RISK_ON: 신규 매수 한도(종목당 20%·4종목)" 처럼 한도의 출처가 남는다. `hedge.agent_gate=false`(또는 `hedge.enabled=false`) 면 tilt 는 늘 0 이라 Phase 17 동작과 같다. 트레이더 md 는 bear + RISK_ON 확신 높음일 때만 `target_weight ≤ 0.10` 매수를 낼 수 있다고 안다. 전략가 제안 적중률(`regime.summary.scorecard`)이 나쁘면 사용자가 꺼야 한다 — 어떤 코드도 자동으로 켜거나 끄지 않는다. RL 사이저 `mode: apply` 는 기존대로 `ml.yaml` 수동(승격 뒤)이다.

## 합의 시 토론 생략(전체 검토 L17, 2026-10-26, `orchestrator/summary.py`·`orchestrator/tools.py`)

**판단은 도구가 한다.** 오케스트레이터는 애널리스트 저장 뒤 `20_debate_*` 가 없으면 먼저 `tool checkpoint summarize` 를 부르고, `checkpoint_summarize` 가 토론 턴이 하나도 없을 때만 `summary.analyst_consensus` 를 본다 — 네 역할(`CONSENSUS_ROLES`) 리포트가 **모두** 있고 신호 방향이 전부 같으며(STRONG_BUY·BUY → BULLISH, SELL·STRONG_SELL → BEARISH, NEUTRAL·UNKNOWN 은 방향 없음 → 합의 아님) 최저 `confidence` ≥ `settings.debate.consensus_min_conviction`(0.7) 이면 `summary.skipped_summary` 로 `25_research_summary{rounds: 0, skipped_debate: true, reason, consensus, sycophantic: null, preferred: null}` 를 쓴다(수렴 감시는 토론 턴이 없어 계산하지 않음). 아니면 `{"ok": false, "debate_required": true}` 로 토론(d·e·f)으로 보낸다. 역할이 하나라도 빠지면(실패·재시도 소진) 합의로 보지 않는다. 토론 턴이 이미 있으면 합의여도 정상 요약이다. `submit-decision` 전제조건(리포트 2개 + `25_research_summary`)은 그대로라 생략 요약도 같은 길로 통과하고, `debate_turns` 원장 행이 없어 `metrics.convergence_rate` 분모에서 빠진다. 트레이더 묶음은 생략 요약을 그대로 싣고(`_trader_summary`), 트레이더 md 가 `skipped_debate` 면 리포트의 `key_risks`·`counter_evidence` 로 반대 논거를 점검하라고 안내한다. FAKE(`fake.run_fake_ticker`)도 같은 순서(가짜 리포트는 NEUTRAL 이라 평소엔 토론). 웹 `pipeline.ts`·`report.ts`·`trace.ts` 는 '토론 생략 · 애널리스트 합의'. 끄려면 `debate.skip_on_consensus: false`. 효과는 섀도 포트폴리오로 2~4주 뒤 비교(TODO).

## 투자 방식 게이트 강화(전체 검토 3차, 2026-10-26, `risk/rules.py`·`risk/costs.py`)

**게이트 강화만(사용자 결정 L9).** 사이징 모델을 새로 들이지 않고 게이트 세 줄로 손실 비대칭을 막는다. ① **1회 손실 한도**: BUY/ADD 수량을 `floor(NAV × risk_per_trade_pct ÷ (주문가 − 손절가))` 로 자른다(기본 2%, `settings.risk.risk_per_trade_pct`) — 목표 비중만 보던 사이징은 손절 거리가 −20% 든 −3% 든 같은 금액을 샀다. 반감 뒤에 적용하고 사유에 손절 거리를 남긴다. ② **손절·익절 필수**: BUY/ADD 에 둘 중 하나라도 없으면 거부(익절가를 비우면 비용 검사를 건너뛰던 구멍). ③ **확신 가중 기대값**: `costs.expected_value = p·(익절/주문가 − 1) − (1−p)·(1 − 손절/주문가)`, p = confidence 를 0.05~0.95 로 자른 값, 이 값이 왕복비용(KR 30bp·US 50bp) 미만이면 거부 — 목표 +2%·손절 −20% 같은 음의 기대값 주문이 기존 '기대수익 ≥ 비용×2' 를 통과하던 것을 막는다. 헤지·단타는 셋 다 면제(각자 전용 규칙), 손절 SELL 은 BUY 분기 밖이라 무관. 트레이더 md 규칙 6 이 같은 조건을 안내한다. 같은 묶음에서 `hedge.agent_signal` 기본을 끄고(L8, 위 「전략가 지표」) 약세 리서처 모델을 강세와 같게(sonnet) 맞췄다(L11 — 비대칭 모델이면 수렴 감시가 정당한 수렴도 아첨으로 본다).

## monitor(스펙 §5.2)

**monitor(스펙 §5.2).** `orchestrator/monitor.check_position` 은 순수 함수: 손절선(결정 `stop_loss`, 없으면 평단 × (1 + `risk.stop_loss_pct`)) 도달이면 손절 신호만, 아니면 take_profit → ±7%(평단 대비) → `invalidation_conditions` 의 가격 조건(`<`/`>=`·`이하`/`이상` + 100 이상 숫자; 거래량·시총·비율 문장은 제외, 숫자가 여럿이면 최대값) 순. **손절선이 현재가 이상인 결정은 `submit-decision` 이 action 과 무관하게 거부한다**(게이트는 BUY/ADD 주문만 막지만 저장된 HOLD/ADD 의 손절선으로 monitor 가 전량 매도하기 때문). 손절은 `executor.execute(is_stop_loss=True, decision_id=<최신 결정 id>)` 로 즉시(approve 계좌도 승인 없이, off 는 기록만, paused 면 안 내고 하루 1회 "손절 보류" 통보). 체크포인트는 오늘 분석의 40_/50_ 을 덮지 않도록 `45_stop_loss_<계좌>`·`55_order_sl_<계좌>` 이며, 같은 날(**시장 현지 날짜**, US 는 KST 자정을 넘겨 장이 열림) 같은 종목의 살아 있는 SELL 이 있으면 다시 내지 않는다(`repo.has_open_order_today(market=, exclude_filled=True)`: 체결이 끝난 TRIM 은 잔량의 손절을 막지 않는다; 원장 status 는 마감 뒤 fills sync 가 바꾸므로 막힐 때만 그 계좌 체결을 1회 동기화해 다시 본다). 접수 뒤 원장 기록이 실패(`OrderBookkeepingError`)하면 다른 종목 점검은 계속하고 `sl_unrecorded:<계좌>:<시장>:<종목>:<날짜>` 플래그로 그날 재발주를 막는다. US 거래소는 `Position.exchange`(잔고 `ovrs_excg_cd`→EXCD) 우선, 없으면 `universe.us`, 둘 다 없으면 NAS 로 추정하지 않고 건너뛴다. 손절은 미승인(pending) 요청에 막히지 않는다(`has_open_order_or_approval(include_approvals=False)`). 시세가 0 이면 건너뛴다. US 손절은 현재가 3% 아래 지정가. 손절 점검(전 계좌)을 먼저 끝낸 뒤 트리거를 처리하고, 재평가 세션 기동 실패와 **떴지만 실패한 세션(`ok=False`)** 모두 트리거에 `실패:` 로 기록하고(`resume.handled_marker`) 다음 종목으로 간다. 오늘 `30_decision` 이 없는 보유분(analyze 미완료·실패)은 세션을 띄우지 않고 트리거만 미처리로 남긴다(submit 이 거부하므로). 같은 종류의 미처리 트리거가 있으면 다시 쌓지 않고 그 행을 재평가에 연결한다. 그 밖의 신호는 `triggers` 행 → `resume.reevaluate` 가 `SessionSpec(kind="resume", trigger=…)` 세션을 띄우고 trader 가 `tool submit-decision --stage 31_decision_r<n>` 으로 제출한다(30_decision 필수, decisions 행은 갱신, 중복 방지는 결정·계좌·방향 키). 재평가의 **현재가는 그날 최신 트리거 가격**(`repo.latest_trigger_price`)이라 손절선 검사·게이트가 아침 시세가 아닌 장중 가격을 쓰고, 트레이더 묶음(`bundle --kind trader`)에는 `previous_decision`(최신 30_/31_)이 들어간다. 같은 종목 재평가는 30분 1회(`triggers.handled_at`)이고 **같은 종류 트리거는 운영일에 1회**(`repo.reevaluated_between`, 기동 실패 `실패:` 는 제외)이며 같은 틱의 트리거들은 세션 1회가 모두 처리한 것으로 표시한다. paused·세션 상한이면 기록만.

## daemon(스펙 §10.1)

**daemon(스펙 §10.1).** `daemon.build_jobs` 가 `schedule.yaml` 을 잡으로 바꾸고(시장별 `<시장>_scan_analyze` cron — scan 시각에 scan 뒤 바로 analyze 를 이어서 돈다, cron 두 개면 screener 가 늦을 때 analyze 가 `_scan` 없이 뜨고 인라인 scan 은 세션이 겹치기 때문; yaml 의 `analyze` 키는 호환용으로 쓰지 않는다 — monitor interval, telegram_poll 30초, fills_sync, reflect·ml_train 자리) `run_job` 이 예외를 `runs` 에 남기고 삼킨다(interval 잡은 오류일 때만 기록해 분 단위 행 폭주를 막는다). 시장 잡은 `should_skip`(paused·**시장 현지 날짜** 기준 주말·KR 휴장일; US 휴장일은 Phase 8)로 건너뛰고 monitor 는 그 시장 `tz` 의 `in_window`(자정 넘김 지원) 안에서만. `schedule.yaml` 의 `us.tz: America/New_York` 으로 US 시각은 뉴욕 시간이며 cron 도 그 tz 로 등록된다. analyze 는 **종목당 세션 1회**(예산은 세션 단위)이고 실패 종목은 통보 후 계속한다. scan 이 예외로 죽어도 analyze 를 시도하며 알림은 `_analyze_body` 가 원인과 함께 1건만 보낸다. SIGTERM 뒤에는 `deps.stop_event` 를 보고 남은 종목 세션을 띄우지 않는다(plist `ExitTimeOut` 은 세션 1회 기준). `schedule.yaml` 의 `analyze` 키는 선택(없어도 됨). `scan_analyze` 잡은 세션을 세기 전에 1시간 넘은 `agent_calls` running 행을 error 로 정리한다(기동 때만이 아니라 매일). `install` 은 `claude` 실행파일 디렉터리를 plist `PATH` 에 넣는다(launchd 는 셸 PATH 가 없다). `Lock` 은 내용이 채워진 임시 파일을 `os.link` 로 원자적으로 잠금 이름에 붙이고(생성→쓰기 두 단계면 빈 파일을 pid 0 으로 읽은 두 번째 데몬이 넘겨받는다; 하드링크 미지원이면 O_EXCL 폴백) pid 생존 확인(`platform/procs.pid_alive`)으로 stale 잠금만 넘겨받으며(pid 를 읽을 수 없는 잠금은 10초 안이면 살아 있는 것), SIGINT/SIGTERM 은 `shutdown(wait=True)` 로 실행 중 잡(analyze 세션)을 기다린 뒤 해제한다(잠금이 세션보다 먼저 풀려 launchd 가 두 번째 데몬을 띄우지 않도록; 대기 중 두 번째 시그널은 무시, plist 는 `ExitTimeOut = llm.timeout_s + 60`). analyze 잡은 `_scan.json` 이 없으면 알림 + `runs` error 로 남긴다(`run_job` 은 `error` 키가 있는 결과를 error 행으로). 로그는 `logging_setup.file_handler`(공유 안전 회전 핸들러)만 쓴다 — 다른 프로세스가 먼저 회전했으면 스트림을 다시 열고, Windows 에서 다른 프로세스가 파일을 쥐어 rename 이 `PermissionError` 면 회전을 건너뛰고 같은 파일에 계속 쓴다(다음 자정 재시도). 오래 사는 단독 명령은 `configure(name=)` 로 파일을 나눈다(`trader web`→`trader-web.log`, `telegram loop`→`trader-telegram.log`, `monitor`→`trader-monitor.log`; 데몬과 짧은 명령은 `trader.log`). 세션 cwd 는 `tempfile.mkdtemp(prefix="trader-claude-")` 로 저장소 밖이며 세션 뒤 삭제한다.

## 세이브티커 수집기(2026-10-27, `trader/saveticker/`)

## 국내 실시간 시세 웹소켓(2026-10-27, `broker/kis_ws.py`·`web/live_quotes.py`)

**국내 실시간 시세 웹소켓(2026-10-27).** 화면 현재가만을 위한 **표시 전용** 경로다(신호·게이트·주문·재시세는 REST 그대로). 웹 프로세스 안의 `QuoteHub` 가 스레드 하나로 KIS 웹소켓(`tr_ids.WS_URL["real"]`, 접속키 `KisAuth.approval_key` — 프로세스 메모 20시간, 거절되면 `invalidate_approval`)에 붙어 국내 체결가 `H0STCNT0` 를 구독한다. 구독 대상은 `/api/quotes?market=KR` 요청이 거는 **임차**(`LEASE_S` 30초)로 정하고 최근 요청 순 40칸(41칸 중 1칸 여유)만, 임차가 끝나면 해제한다 — 브라우저는 지금처럼 보이는 탭이 폴링하므로(응답 `stream: true` 면 1초, 아니면 10초) 탭이 늘어도 KIS 연결은 하나다. 라우터는 허브에 틱이 있는 종목은 그 값(`source: "ws"`), 나머지는 기존 REST(5초 캐시)로 채운다. 허브는 첫 장중 요청에 뜨고 정규장이 아니거나 60초 동안 요청이 없으면 닫는다. 프레임은 여러 건 묶음(세 번째 칸 건수)을 46칸씩 자르고 전일대비부호 4·5 는 등락률을 음수로, `PINGPONG` 은 그대로 돌려보내고(안 하면 서버가 끊는다), 접속 실패는 지수 백오프(최대 30초), 거절된 종목은 다시 청하지 않는다. US 는 웹소켓 대상이 아니다(10초 REST). 설정 `settings.web.realtime_ws`(기본 켬). **확장(2026-10-27)**: 같은 허브·같은 연결로 지수 `H0UPCNT0`(KOSPI 0001·KOSDAQ 1001, `GET /api/quotes/indices` → 상단 바 `IndexChips`, 장중 2초)와 호가 10단 `H0STASP0`(`GET /api/quotes/book?ticker=` → 차트 `OrderBook`, 임차 10초·1칸·1초) — 41칸 = 지수 2 + 호가 1 + 체결가 37 + 여유 1. 구독 키는 (TR, 키) 튜플. **체결통보**(`orchestrator/notice.NoticeListener`, Stock D-060)는 데몬이 계좌 env 마다 따로 연결해(모의 31000·실전 21000, 데몬 수명 동안) 국내·해외 통보 TR 을 HTS ID(`secrets KIS_HTS_ID`)로 구독하고, 암호화된 통보 프레임은 풀지 않고 '동기화하라' 신호로만 써서 `jobs.enqueue("fills_sync")`(빠른 레인, 5초 디바운스, 중복은 무시) — 반영 규칙은 `fills.sync_fills` 그대로. HTS ID 거절이면 그 env 는 멈추고 정기 동기화만, `settings.fill_notice`(기본 켬). **앱키당 세션 하나**(KIS): 실전 env 리스너는 시세 허브와 같은 실전 앱키라, 실전 계좌의 유효 모드가 off 가 아닐 때만(`cli._notice_enabled`, 30초 캐시) 붙고 그동안 같은 프로세스(데몬 안 웹)의 허브는 `blocked()` 로 비켜선다(화면은 REST 10초) — 모의 env 는 모의 앱키라 늘 켠다. 다른 프로세스(단독 `trader web`, 옛 Stock 등)가 쥐고 있으면 'ALREADY IN USE appkey'(`kis_ws.is_appkey_in_use`)로 끊고 백오프하며, 리스너는 다시 붙는 순간 보충 동기화로 빈 구간을 채운다.

## Stock 교훈 1차 — 안전장치·판단 근거(2026-10-27, `docs/superpowers/plans/2026-10-27-stock-lessons-1.md`)

**Stock 교훈 1차(2026-10-27).** 중단한 Stock 프로젝트의 결정 기록에서 가져온 것 중 매매를 늘리지 않고 막거나 재는 것만. 전부 파이썬 규칙이고 LLM 경로는 그대로다.

- **매매 제한 종목**(`risk/tradability`, D-030): 국내 현재가 응답의 종목상태(51 관리·52 투자위험·53 투자경고·58 거래정지·59 단기과열)·시장경고(02·03)·임시정지를 `Quote.status_code/warn_code/halted` 가 싣고 `00_inputs` 로 온다. `tools._trade_block` → `executor.execute(trade_block=)` → 게이트가 BUY/ADD 거부(매도 무관). US 는 판정 없음.
- **지수 섀도 기준선**(`ledger/shadow` `index_hold`·`index_trend`, D-037~D-039): Stock 의 규칙 조합은 3년간 KOSPI 보유를 못 이겼다. 지수 proxy(`hedge.index_proxy`) 보유와 100일선 위면 보유·아래면 현금을 운영일마다 기록·5거래일 만기 채점한다. proxy 는 피처 스토어에 없어 기록·만기 때 `shadow.index_table`(KIS 일봉)을 넘긴다. 성과 페이지 'LLM 종목 선택 효과' 에 기준 4개(readiness 의 `llm_alpha` 는 후보 1/N 기준 그대로).

- **생존 편향 경고**(D-037): `ml train` 결과·모델 메타에 `caveats`(현재 구성 종목으로 과거 학습 → 알파 과대 가능).
- **시점 기준 유니버스**(`ml/universe_pit`, 원장 v24 `universe_members`, 2026-10-27): 과거 구성원·상장폐지 목록은 무료로 얻을 길이 없어 **오늘부터 기록**한다 — 데몬 cron `universe_members`(매일 06:40 KST)가 그날의 유니버스(제외 목록 뺌) + 계좌 보유(헤지·현금 운용 ETF 뺌)를 **구간**(first_seen·last_seen, 기록 사이가 7일 넘게 벌어진 재편입은 새 구간 — 재편입이 편출 기간을 소급해 덮지 않는다)으로 남긴다. 효력일은 `universe_pit.effective_day`: 그 시장 정규장이 끝난 뒤의 관측은 다음 날부터(US 는 06:40 KST 가 뉴욕 장 마감 뒤라 다음 거래일). `train.prepare_dataset` 는 라벨을 종목의 연속 봉으로 먼저 계산한 뒤 `universe_pit.apply` 로 기록 시작일 이후 행을 그날 구성원(어느 구간이든 마지막 기록 + 5일 유예)만 남기고, `relative_tercile` 이면 남은 모집단 안에서 삼분위를 다시 매긴다(빠진 종목의 수익이 순위를 오염시키지 않게). strict 에서 기록을 읽지 못하면 학습을 멈춘다 — 편출·상장폐지 종목의 과거 행은 피처 스토어에 남아 학습에 들어간다. 기록 전(현재 구성으로 백필한 과거) 날짜는 `ml.train.pit.strict` 가 꺼져 있으면 그대로 쓰고, 학습 결과·모델 메타 `pit.coverage`(기록이 덮은 행 비율)와 생존 편향 경고에 그 비율을 남긴다(coverage 1 이어도 편출 종목의 편출 뒤 봉은 수집하지 않아 마지막 라벨이 빠진다는 잔여 경고 `EXIT_CAVEAT` 는 남는다). `liquidity_top_n` 은 걸러내기 전 전체 봉을 (시장·종목·날짜) 순으로 굴린 그날까지의 `liquidity_window` 일 평균 거래대금 상위 N 만(기본 0 = 끔).
- **단타 켜기 전 조건**(D-120): Stock 은 1분봉 약 1년·53종목 재생에서 단타 규칙 11개가 모두 비용 뒤 손실이었다. `scalp.enabled` 를 켜기 전에 수개월 분봉 재생·비용 반영·보류 구간 1회 검증을 거친다(코드 강제 없음, 운영 규칙).

## ML(스펙 §9, `ml/`)

**ML(스펙 §9, `ml/`).** 라벨은 같은 종목 `horizon_days`(5) 뒤 종가 수익률이며 `label.mode` 가 `absolute` 면 ±2% 3분류, `relative_tercile`(현재 설정) 이면 같은 날·같은 시장 안 순위 삼분위(기준선 1/3 고정, 같은 날 종목 3개 미만이면 NaN; scan 랭커 용도와 맞음). 미래 봉 없는 행은 라벨 NaN. `05_quant` 는 `label_mode` 를 실어 트레이더가 상대 순위 확률과 상승 확률을 구분한다. 워크포워드는 비중첩 테스트 창 + 엠바고(학습 마지막 날짜는 `test_start − (horizon + embargo) − 1` 거래일 이전), 역검증 테스트(라벨 섞기·타깃 열 거부)가 있다. 승격(`train.promotion_decision`)은 `promote_metric` 에 따라 — `accuracy`: 합산 정확도가 **기준선(최빈 라벨 비율)을 넘고** ≥ `promote_min_accuracy`(0.40), 알파 > `promote_min_alpha`; `alpha`(현재 설정): `alpha_topn`(날짜·시장마다 p_up 상위 `promote_top_n`(5) 종목의 수익 − 그날 유니버스 평균을 날짜 평균; scan 랭커가 실제로 쓰는 방식, 풀링 `alpha` 는 참고용)의 폴드 평균 ≥ `promote_min_alpha`(0.003 = KR 왕복비용; `promote_min_alpha_by_market`(US 0.005 = US 왕복 50bp)가 시장별로 우선, `QuantModelCfg.min_alpha_for(market)` 하나로 읽는다) ∧ 양인 폴드 비율 ≥ `promote_min_positive_folds`(0.66 = 6폴드 중 4) — 두 모드 모두 모든 폴드의 up 예측 ≥ `min_up_predictions`(5) 일 때만이며(잡음·전부 중립 모델이 통과하지 않도록), `ml train --horizon N` 은 그 실행만 `horizon_days` 를 덮어쓴다(실험용), **승격 모델이 없으면 `05_quant` 도 ML 랭킹도 없이 파이프라인이 돈다**. 하이퍼파라미터(`learning_rate`·`num_leaves`·`max_iter`)는 `ml tune`(`ml/tune.py`)이 워크포워드 **마지막 폴드를 홀드아웃으로 떼고** 나머지(dev) 폴드의 alpha_topn 으로만 후보를 고르며, 홀드아웃은 기본값·최선 후보 두 번만 평가해 보고한다(`state/models/quant_tune/<ts>.json`). 어떤 코드 경로도 탐색 결과를 자동 적용하지 않는다 — 리포트의 `recommendation.apply`(홀드아웃 alpha_topn 이 승격 기준과 기본값을 모두 넘을 때만 true, 동률은 기본값 우선, dev 폴드가 하나도 평가되지 않으면 `insufficient_folds`)가 true 일 때 사용자가 `ml.yaml` 에 반영한다. 적용 뒤 `ml train` 의 승격 지표는 선택에 쓴 dev 폴드를 다시 쓰므로 낙관적이다(승격 게이트 폴드는 바꾸지 않는다). sklearn 백엔드는 `early_stopping=False` 다(auto 는 1만 행 넘으면 무작위 10% 검증으로 조기 종료해 `max_iter` 가 무의미하고 시간 순서를 섞는다). 투입 지점은 둘뿐: `tools.ensure_quant`(`tool collect`·`analyze`·데몬 analyze 뒤 `05_quant` 저장 → 트레이더 `context.quant`)와 `ml/ranker.current()`(scan `rank_fn`). 부스팅 반복은 `models.quant.max_iter`(기본 200, 테스트는 `helpers_ml.fast_cfg` 40). 모델 백엔드는 `ml.yaml` `models.quant.backend`(코드 기본 `sklearn`; 설정 파일은 `auto` = lightgbm 이 import 되면 lightgbm, 아니면 sklearn — 모델 메타 `backend` 에 실제 값이 남는다; `lightgbm` 은 선택 extra `uv sync --extra lightgbm` + macOS `libomp`, 번들은 lightgbm 을 넣지 않아 sklearn 으로 돈다). `models.quant.enabled`·`ranker.enabled` 가 꺼지면 투입 지점이 모두 None 을 돌려주고, 레지스트리·모델 로드 오류는 경고만 남기고 ML 없이 진행한다(`ml demote <버전>` 으로 승격 해제; lightgbm 으로 학습한 모델을 lightgbm 없는 환경이 못 읽으면 경고에 그 원인과 demote·sklearn 재학습 안내를 붙인다). 레지스트리는 `state/models/quant/<YYYYMMDD_HHMMSS>/`. 전부 NaN 인 피처 열은 학습에서 제외하고 예측 때 같은 마스크를 쓴다.

## 작업 대기열(Phase 17)

**작업 대기열(Phase 17).** 웹·데몬·CLI 의 '지금 실행' 요청은 원장 `job_requests`(v11) 한 곳에 `jobs.enqueue` 로만 넣고(kind·params 는 `jobs.PARAMS` pydantic 이 유일한 검증, 같은 kind+params 가 queued|running 이면 `DuplicateRequest`), **실행 주체는 데몬의 `job_queue` interval 잡(10초, 한 틱에 1건)뿐**이다 — 단독 `trader web` 은 데몬이 죽어 있으면 `POST /api/control/jobs` 를 409 로 거절한다(`heartbeat.read_status` 의 alive). kind 는 `scan_analyze`(사용자가 눌렀으므로 주말·휴장 `should_skip` 미적용)·`analyze_ticker`(`_analyze_targets`, `dry_run = deps.dry_run or 요청값` 이라 데몬 --dry-run 을 웹이 뒤집지 못함, US 거래소는 `universe.us` 로 보강)·`features_backfill|snapshot|derive`(`DaemonDeps.features_fn`, `cli._daemon_features_fn`)·`ml_train`·`rl_train`·`reflect`·`fills_sync`. 무거운 잡은 `DaemonDeps.heavy_lock` 으로 한 번에 하나(cron 의 scan_analyze·reflect·ml_train 은 기다리고, 대기열 틱은 잠겨 있으면 claim 하지 않고 다음 틱), 요청 실행도 `run_job` 을 지나 `runs`·하트비트 정책이 그대로이며 이름은 `jobs.job_id_for`(`scan_analyze{KR}`→`kr_scan_analyze`)라 잡 표에 섞여 보인다. 진행 문구는 `job_requests.progress`(1초 스로틀, `_progress_writer`) 이고 SSE 스냅샷에는 넣지 않는다(활성 요청이 있을 때만 프런트가 3초 폴링; 스냅샷은 `job_requests`·`jobs_active`·`jobs_done`). 기동 때 `_bootstrap_queue`: running→error(재실행 안 함), 6시간 넘은 queued→skipped, 피처 스토어가 비면 `features_backfill{years:3}`+`ml_train` 자동(24시간 안 실패 기록이 있으면 생략). RL 사이저 주간 학습은 `rl_sizer.enabled` 와 무관하게 늘 돈다(적용은 승격·enabled). `job_queue` 의 APScheduler MAX_INSTANCES 는 missed 로 적지 않는다. 웹은 `components/RunJob.tsx` 의 `RunJobButton` 하나로만 요청한다(세션 비용·주문 가능 작업은 확인창).

## 시장 세션(Phase 18, `orchestrator/market_view.py`)

**시장 세션(Phase 18, `orchestrator/market_view.py`).** 하락장 대응에 에이전트를 **제안자**로 붙인다 — 결정은 여전히 파이썬. 데몬 `_scan_analyze_body` 가 `_regime_body` 뒤 `_market_view_body` 로 시장별 운영일 1회(`hedge.market_session`, 오늘 `control.market_view:<market>` 가 있으면 생략, 세션 상한이면 생략) `kind="market"` 세션을 띄운다: 파이썬이 `_market_inputs`(국면·지수 proxy 60봉·FRED 거시·구글뉴스 거시 10건·`_market_<시장>.md` 수동 입력·헤지 설정/보유·모의 계좌 섹터 비중, 전부 `asof` 이하)를 `market_dir` 에 쓰고, 오케스트레이터가 `tool market bundle --kind analyst|researcher|strategist` → `analyst-market`(AnalystReport, role `news_macro`, ticker 는 proxy 라벨 `KOSPI200`|`SPX`) → `researcher-bull/bear`(입력 `scope:"market"`, DebateTurn) → `tool market summarize`(`_market_summary`, 수렴 감시 동일) → `strategist`(HedgeProposal) → `tool submit-market-view`(`_market_analyst`+`_market_summary` 전제, `_market_view.json` + 플래그 `{date,…}`). 시장 단계 파일은 전부 `_market_*` 이고 종목 경로(`@_guarded`)와 섞이지 않는다. 규칙 연결은 `hedge.rebalance` 한 곳: 오늘 제안이 있으면 bear 진입 비중을 `[hedge.min_weight_pct(0.05), max_weight_pct]` 로 자르고(`market_view.clamp_weight`) `leveraged=false` 면 3/3 이어도 −1x; **bear 가 아니면 RISK_OFF 제안이 와도 진입하지 않고**, 해제·어제 제안(`date` 불일치)·세션 실패는 Phase 17 규칙 그대로(max 비중). 트레이더는 `context.market_view`(오늘 것만) 를 받고, 가시성은 `regime.summary(today=)` 의 `view` → `/api/system/regime`·대시보드 칩 "(KR 제안 12%)"·STATUS·텔레그램 `/status`(`regime.line`). 작업 대기열 kind `market_view{market}`(HEAVY). `FAKE_CLAUDE=1` 은 `fake.run_fake_market`(bear 면 RISK_OFF 0.10, 아니면 RISK_ON 0).

## 하락장 대응(Phase 17 H)

**하락장 대응(Phase 17 H).** 전부 파이썬 규칙이고 LLM 은 `context.regime` 으로 상태만 받는다(Phase 18 의 시장 세션은 비중 제안만, 위 단락)(공매도는 KIS 개인 API 미지원이라 제외). 국면은 `risk/regime.py`: 지수 proxy(`hedge.index_proxy`, KODEX 200 `069500`·SPY) 일봉으로 ① 종가 < 200일 SMA ② 20거래일 수익률 ≤ −5% ③ 변동성(US 는 FRED VIX ≥ 25, KR 은 20일 실현변동성 연율 ≥ 25%) 을 세어 `count ≥ bear_min_signals(2)` → bear, 0 → bull, 그 외 neutral 이며 bear 해제는 `count ≤ 1` 이 `exit_streak_days(5)` 연속일 때(히스테리시스). 상태는 `control.regime:<market>` 하나(`regime.update`, 같은 운영일 재호출은 streak 을 겹치지 않음)이고 데몬 `_regime_body` 가 `<market>_scan_analyze` 맨 앞에서 갱신한다(실패하면 직전 상태 유지 + 경고, 전환은 알림). 게이트(`rules.evaluate(regime=, is_hedge=, hedge_max_weight=)`): neutral 은 신규 BUY/ADD 한도를 종목당 15%·3종목(`stance.limits_for_regime`)으로, bear 는 일반 BUY/ADD 거부(SELL·TRIM·손절·헤지만 통과), **섹터 상한**(`risk.max_sector_pct` 0.40, `config/sectors.yaml` 의 `SectorMap.sector_of`, 모르면 `기타`)은 BUY/ADD 뒤 같은 섹터 합계가 넘으면 거부하고 헤지 ETF 는 섹터·종목 수 계산에서 뺀다(`Portfolio.equity_positions`). 헤지(`orchestrator/hedge.rebalance`)는 monitor 잡의 그 시장 첫 창 안 틱에서 운영일 1회(`control.hedge_done:<market>:<date>`): bear 이고 미보유면 상품(`count==3 ∧ hedge.leverage` 면 −2x `252670`/`SDS`, 아니면 −1x `114800`/`SH`) BUY `target_weight=hedge.max_weight_pct`(0.20), bear 가 아니고 보유면 전량 SELL, 보유 중 상품 교체는 없다. 주문은 파이썬이 만든 `Decision`(`repo.insert_hedge_decision`, `decisions.source='hedge'`, v12 — 결정 분포·메모리·복기에서 제외)을 `executor.execute(is_hedge=True)` 로 보내 계좌 모드(off/approve/auto·LIVE 확인·paused·dry_run)를 그대로 지키며 체크포인트는 `46_hedge_<계좌>`·`56_order_hedge_<계좌>`, 면제 규칙은 비용·보유기간·주 2회·중복·종목 수·섹터·일일손실, 비중 상한만 헤지 값. monitor 는 헤지 ETF 를 건너뛰어(손절·트리거 없음) 헤지는 국면 해제로만 판다. US 헤지 ETF 거래소는 `AMS` 로 두되 실기 `universe check` 로 확인한다. 가시성은 `regime.summary/line` 하나로 `/api/system/regime`·대시보드 칩·STATUS '## 국면·헤지'·텔레그램 `/status`·`trader regime show`.

## KIS 실패는 전부 `KisApiError(msg_cd, msg1, tr_id)`

**KIS 실패는 전부 `KisApiError(msg_cd, msg1, tr_id)`.** KIS 응답이 아닌 실패는 합성 코드 `AUTH/NETWORK/NETWORK_UNKNOWN/HTTP<status>/INVALID_JSON/UNSUPPORTED`(`NETWORK` 는 보내지도 못함, `NETWORK_UNKNOWN` 은 보낸 뒤 응답 없음 — 주문이 살아 있을 수 있어 executor 가 구분한다). KR 분봉 역방향 페이징의 "짧은 페이지" 판단은 빈 시각 행을 버리기 전 원시 행 수로 한다. 토큰은 `state/kis_token_<env>.json` 캐시(만료 1시간 전 갱신, 실패 후 60초 재발급 금지, 실패 기록은 발급 전 스냅샷이 아니라 다시 읽은 파일에 덧붙여 다른 프로세스가 막 쓴 토큰을 지우지 않음). `EGW00201`(초당 한도)은 HTTP 200 뿐 아니라 **HTTP 500 본문**으로도 오므로 상태코드와 무관하게 0.5·1.0·2.0초로 최대 3회 물러나 재시도한다(백필 연속 호출에서 1회로는 종목이 통째로 빠졌다, 실기 2026-10-20). 모의 서버는 2/s 라 한 점검에서 같은 API 를 두 번 부르지 않는다. US 예수금은 `inquire-present-balance`(통화별 행) 로 읽는다. `inquire-psamount` 는 종목코드 필수라 현금 조회에 못 쓴다(실기 확인). 일봉·수급 목록은 **항상 날짜 오름차순**(마지막이 최신). 금액은 `Decimal`. `OrderRequest.exchange` 는 기본값이 없어 KR 도 `None` 을 명시한다.

## 계좌별 키·연결 키 입력(2026-10-27)

**같은 명의의 계좌 여럿.** 한국투자증권은 앱키를 계좌마다 발급하므로 계좌마다 키 묶음을 고른다: `Secrets.kis_creds(account)` 가 계좌 전용 접두사(`accounts.yaml credentials`, 없으면 id 로 정한 `KIS_<ID>_` — real-2 → `KIS_REAL_2_`)에 `APP_KEY` 가 있으면 그 묶음(`APP_KEY·APP_SECRET·CANO·HTS_ID`), 없으면 env 공용(`KIS_PAPER_*`·`KIS_REAL_*`, HTS ID 는 `KIS_HTS_ID`). 계좌 전용 키는 `Secrets` 의 추가 값(`extra="allow"`, `Secrets.get`)이고 환경변수 `KIS_*_<접미사>` 가 덮어쓴다. `cli._client_for(creds)` 가 앱키마다 `KisClient` 하나 — 토큰 캐시 `state/kis_token_<bucket>.json`·교차 프로세스 레이트리미터 버킷이 앱키 단위(`KisCreds.bucket` = `<env>-<앱키 지문 sha256 12자>` — 같은 키를 두 이름으로 넣어도 하나, 키를 바꾸면 새 캐시)라 키끼리 덮어쓰거나 한도를 나눠 먹지 않고, 캐시 파일에도 앱키 지문(`key`)을 남겨 다른 키로 받은 토큰은 읽지 않는다(지문 없는 옛 파일은 그대로 쓴다). 전용 키를 골랐으면 계좌번호도 그 접두사의 `CANO` 만(다른 계좌 공용 번호를 빌리지 않는다). 웹 입력은 `${…}`(dotenv 보간)를 거부한다. 두 계좌가 같은 키 묶음으로 풀리면 `_build_brokers` 가 경고한다(다른 계좌를 그 앱키로 부르면 KIS 가 거부할 수 있다). 시세는 공용 실전 키, 없으면 첫 실전 계좌의 전용 키(`_market_creds`). **체결통보는 (env, HTS ID) 마다 리스너 하나** — 통보는 HTS ID 단위라 같은 명의 계좌 전부를 연결 하나로 받고, 실전은 시세 허브가 쓰지 않는 전용 키가 있으면 그 키로 붙어(`shares_market_session=False`) 앱키 세션 충돌이 없다. 그 HTS ID 의 실전 계좌가 하나라도 off 가 아니면 켠다.

**연결 키 입력(설정 화면).** `secrets_io.catalog` 가 입력할 수 있는 이름(공용 KIS·알림·데이터 + 계좌마다 전용 4칸, `WEB_TOKEN` 제외)을 정하고 `POST /api/control/secrets/status`(이름·묶음·`set` 여부·계좌별 사용 키 — **값은 돌려주지 않는다**, 판정은 실제 로더 `load_secrets`(.env + 환경변수)와 같고 환경변수가 덮는 칸은 `env: true` → 화면 '환경변수 우선')·`POST /api/control/secrets`(`values`·`clear`, 목록 밖 이름·공백·여러 줄·따옴표/# 시작 거부, 바꾸기 전 `.env.bak-<YYYYMMDD_HHMMSS>`, 임시 파일 → 원자 교체, 0600, 백업~교체 전체를 스레드 락 + `.env.lock` 파일 락으로 한 번에 하나 — 동시 저장이 서로 지우지 않게)는 토큰 + `auth.is_direct_local`(루프백 클라이언트 ∧ 루프백 Host ∧ 프록시 헤더 없음 — tailnet 폰 요청 거부). 실행 중인 데몬·웹은 시작 때 읽은 키를 쓰므로 응답 `restart_required` 로 재시작을 안내한다. **웹 토큰 자동**: `_web_deps` 가 `WEB_TOKEN` 이 없으면 `secrets_io.ensure_web_token` 으로 만들어 .env 에 넣고(값은 로그에 없음), `GET /api/control/bootstrap-token` 은 이 PC 직접 접속 ∧ `Sec-Fetch-Site: same-origin`(다른 사이트의 요청은 브라우저가 이 헤더를 위조하지 못한다)일 때만 토큰을 준다 — 프런트 `useAppState` 가 토큰이 없으면 한 번 받아 둔다. 폰은 설정 화면에 직접 넣는다.

## 수집 계층(`sources/`)

**수집 계층(`sources/`).** `build_inputs` 는 이름·기술 절 뒤 `fundamental`·`news_macro`·`sentiment` 를 스레드풀(3)로 동시에 돌린다(KIS 는 `RateLimiter` 락, DART 고유번호 맵은 자체 락). 모든 수집기는 `base.run_section` 을 거쳐 `Section{data, received_at, error}` 를 돌려주고 예외를 던지지 않는다. 수집기가 `http` 주입 없이 스스로 만든 `httpx.Client` 는 `base.owned_client` 로 블록 끝에 닫고, 주입된 클라이언트는 호출자의 것이라 닫지 않는다. 호출 없이 건너뛸 때는 `skipped_section(reason)`. `SKIP_REASONS = {disabled, phase6, not available for US}` 는 `00_inputs.errors` 에 집계하지 않고, 그 밖의 error(`no api key`, `no market client`, 예외 문자열)는 `<역할>.<키>: <오류>` 로 모인다. 뉴스·커뮤니티처럼 절 안에 소스별 결과(`data.sources`)가 있으면 그 하위 실패도 `<역할>.<키>.<소스>: <오류>` 로 덧붙인다. 종목명은 KR 이 DART → KIS(`get_name_kr`) 순, US 는 EDGAR 티커 맵 순으로 폴백한다. `00_inputs.json` 키 배치는 `technical{quote, daily, minute, orderbook, indicators}`, `fundamental{ratios, history(KR: DART 3개년+최근 분기 v2; US: EDGAR 10-K 3개년 `years`(end 연도 키, `_전기` 없음)+최신 10-K 뒤 최근 10-Q `latest_quarter`(form·end·filed), `edgar.financial_history_us`; 정정 공시 10-K/A·10-Q/A 는 같은 결산일 원본을 덮되 asof 까지 제출분만; companyfacts 는 **메모하지 않고** 한 수집 안에서 호출자가 facts 를 들고 비율·history 에 같이 넘긴다 — 데몬이 클라이언트를 재사용하므로 프로세스 수명 메모는 새 10-Q 를 영영 못 본다), disclosures, peer(v3: 피처 스토어 최신 행(시장 현지 운영일 이하)의 같은 섹터 중앙값·내 값·차이, 섹터 미상·3종목 미만이면 `no sector peers` 건너뜀)}`, `news_macro{news, macro(항목별 Section dict)}`, `sentiment{investor_flow, short_interest, community, trends, manual_inputs}` + `meta` + `errors`. 저장 전 `Decimal` → 문자열, 날짜 → ISO 로 바꾸므로 읽는 쪽은 `Decimal(str)` 로 되돌린다. 구조를 바꾸면 `inputs.SCHEMA_VERSION` 을 올린다. DART·EDGAR 비율은 같은 한글 키(`매출성장률·영업이익률·ROE·부채비율·PER·PBR·PSR`)로 `dart.basic_ratios()` 를 공유한다. DART 는 오류를 zip 이 아닌 XML(`status` 800 점검 등)로도 주므로 `DartError` 로 통일한다.

## 피처 스토어(`ml/features.py`)

**피처 스토어(`ml/features.py`).** `state/features/<date>.parquet`, 키 `(date, ticker)`, 쓰기는 멱등. 수급은 KR 만, 비율은 KR 은 DART·US 는 EDGAR companyfacts 연도별 값(`edgar.ratios_by_year_us`: 사업연도 Y 값은 Y+1 년 4월 1일까지 제출된 10-K 로만 — KR 과 같은 룩어헤드 규칙, 지연 제출은 다음 해로)으로 채우고 클라이언트가 없으면 NaN. 동종업 상대 비율 `*_vs_sector`(`features.add_sector_relative`) 는 비율 − 같은 날·같은 시장·같은 섹터(`config/sectors.yaml`, 사람이 관리) 중앙값이며 값 있는 구성원이 3개 미만이거나 섹터를 모르면 NaN(0 이 아님). `write_rows` 가 합친 날짜 파일 **전체**로 다시 계산해 묶음 쓰기 뒤에도 멱등이고(백필은 `derive=False` 로 묶음을 쓰고 끝에 건드린 파일만 `rederive(paths=)` 1회 — 날짜 × 묶음 수만큼 재계산하지 않도록), `features derive`(`rederive`) 가 옛 파일을 KIS 호출 없이 올린다. `sector_medians`(peer 절)는 종목별 최신 행이라 `dates{min,max}` 로 섞인 날짜 범위를 드러낸다. 웹 탐색은 `latest_rows`·`ticker_history`(최신 파일부터 필요한 만큼, parquet 행 필터)로만 읽고 유니버스에 없는 종목은 404 다. `write_rows` 는 식별 열(`KEY_COLUMNS`) 누락을, `snapshot_row` 는 피처 열 누락을 ValueError 로 막는다(`_coerce` 가 reindex 라 조용히 NaN 이 되지 않도록). 데몬 스냅샷(`cli._daemon_snapshot_fn`)도 CLI 와 같은 `_build_edgar()` 를 넘긴다. `snapshot` 행의 date 는 asof 가 아니라 마지막 일봉 날짜. 지표 워밍업 구간도 NaN 인 채로 저장한다. 백필은 KIS 일봉 상한 1,000봉에서 자르고 DART 실패 시 가격 지표만 저장한다. `state/cache/` 7일 캐시는 DART 기업코드 맵·EDGAR 티커 맵·KIS 휴장일만 대상이다.

## 메모리(스펙 §6.5, `memory/`)

**메모리(스펙 §6.5, `memory/`).** `submit-decision` 이 결정·라운드마다 `memory_entries` 1행(원장 v23 `UNIQUE(decision_id, round)`, 멱등)을 12차원 상황 벡터(`memory/vector.DIMS`)와 함께 쓴다. 아침 `30_decision` 은 `round` 0, 장중 재평가 `31_decision_r<n>` 은 `round` n 의 **별도 엔트리**다(전체 검토 L2 — 예전엔 재평가가 아침 엔트리의 action 을 덮어써 아침 판단이 오후 결정으로 채점됐다). 엔트리의 `decided_at` 은 실행 **직전** 시각이고(그 라운드의 주문이 뒤에 생겨 체결 창이 된다) `held_at_decision` 은 방금 판정이 남긴 잔고 스냅샷(주문 전)의 보유 여부다(`store.held_at`: 그 날짜 이하 최신 스냅샷, 스냅샷이 없으면 NULL=모름). `reflect`(`outcomes.mature`)가 만기 뒤 채점한다(전체 검토 L3): **`direction_score`** 가 판단 품질의 기준(BUY/ADD +ret, SELL/TRIM −ret, HOLD 는 결정 때 보유면 +ret·미보유/모름이면 0 — 관망은 손익이 없다, ret = 결정일 종가 → horizon 거래일 뒤 종가), `avoided_loss` 는 SELL/TRIM·미보유 HOLD 의 max(0, −ret)(그 외 NULL), `realized_pnl_pct` 는 그 라운드 창(이 엔트리 decided_at ≤ 주문 < 다음 라운드 decided_at, 같은 결정·계좌·방향)의 실제 체결 평균가 → 만기 종가 수익에 방향 부호(체결 없으면 NULL). 보유 여부가 엔트리에 없으면(옛 행) 결정일 `positions_snapshot` 으로 정한다. 결정의 **운영일**은 `decided_at` 의 KST 날짜가 아니라 결정 행 `decisions.date`(US 는 뉴욕 날짜 — 자정 넘긴 US 결정도 실제 시각을 남긴다)로 읽는다: 만기 가격 창·신호 보정 조인·복기 신호·백테스트·RL 데이터셋 모두(결정 행이 없을 때만 KST 날짜). `realized_return·alpha_vs_benchmark`(HOLD 0·알파 −벤치마크, SELL 가상 공매도)는 하위 호환으로 계속 채우되 트레이더 입력·복기·보정은 `direction_score` 를 본다. v23 은 `decision_id UNIQUE` 를 풀려고 테이블을 다시 만들고(행·id 보존, 전부 round 0) 만기 행의 `direction_score·avoided_loss` 를 `price_return`·결정일 스냅샷으로 채운다(옛 행의 action 은 재평가가 덮어쓴 값일 수 있어 복원 불가, `realized_pnl_pct` 는 NULL). 재평가 엔트리는 검색 점수 × `store.REEVAL_WEIGHT`(0.5)이고 `matured_count`(워밍업·보정 기준)·백테스트·RL 데이터셋·섀도 조인은 round 0 만 본다. **Outcome Embargo**: 결과가 채워진 엔트리만 트레이더 입력·보정·백테스트에 들어간다. 검색은 `store.retrieve` 점수 0.4 recency(3층 반감기 14/90/365일) + 0.4 코사인 + 0.2 importance 로 상위 `top_k`, 만기 결정이 `warmup`(50) 미만이면 `memory_status.warmup=true` 로 빈 목록. 서킷브레이커는 **시장별** 플래그 `control.memory_breaker:<market>`(시장 없는 전역 키는 모든 시장에 적용)로, 모의 계좌 판정(`build_portfolio`) 때 그 시장 NAV 드로다운(`settings.memory.drawdown_stop_pct`)과 `control.vix_last`(트레이더 입력 묶음 때 `00_inputs.news_macro.macro.vix` 를 기록, 직전 다른 날짜 대비 변화율 ≥ `vix_spike_pct`)로 갱신되며 켜지면 그 시장의 메모리 입력이 비워진다. KR 판정이 US 플래그를 건드리지 않는다. `price_return`(원시 가격수익)을 `realized_return`(방향 기준)과 따로 저장해 HOLD 결정도 신호 채점에 쓴다. 승격은 |direction_score|(없으면 실현수익) 또는 회피 손실 ≥ 5% 또는 반성 lesson, 삭제는 importance < 0.2 의 short 층만.

## 보정(스펙 §9.3, `calibration/`)

**보정(스펙 §9.3, `calibration/`).** `35_calibration` 은 `ensure_calibration` 이 `ensure_quant` 뒤에 만들며 `ml.yaml models.calibration.enabled` 가 꺼져 있거나 만기 결정이 `min_decisions`(60) 미만이면 체크포인트를 만들지 않는다(트레이더는 `context.calibration` 없음으로 동작). 역할별 적중률은 상황 벡터 코사인 상위 k=20 이웃 가중. 신호 적중은 가격 방향 예측이라 `price_return` 부호로 채점하고 보고서가 아침 분석의 것이라 round 0 엔트리만 조인한다. 결정 품질 `decisions`(`model.decision_quality`: `direction_score` > 0 비율 — 미보유 HOLD 의 0 은 분모 제외, 평균 방향 점수·회피 손실, 재평가 라운드 가중 `REEVAL_WEIGHT`)를 함께 낸다.

## RL 사이저(스펙 §9.4, `ml/rl/`)는 실험이며 모의 계좌 한정이다

**RL 사이저(스펙 §9.4, `ml/rl/`)는 실험이며 모의 계좌 한정이다.** 스텝 = 만기 메모리(≥ `min_memory_steps`) 아니면 피처 스토어 전 행(확신 0.5·LLM 비중 0 의 가상 BUY), 환경 관측 16차원(상황 벡터 12 + 확신·LLM 비중 + 현재 비중·드로다운), 행동 비중 0~0.25, 보상 = w·r − 회전 비용 − 드로다운 페널티. CEM 은 모집단을 `learners.population_rewards` 로 한 스텝 루프에서 벡터 평가한다(`_episode_reward` 루프와 동치 테스트). 학습은 quant 와 같은 워크포워드 폴드·엠바고에 시드 N 회, 기준선 3종(고정·LLM·변동성 타깃)과 함께 레지스트리 `rl_sizer` 메타 `summary` 에 남기며 **어떤 코드 경로도 자동 승격하지 않는다**(`rl promote` 만). 백엔드는 `cem`(numpy, 플랫폼 동일) 기본, `ppo` 는 선택 extra `rl`(`auto` 는 SB3 가 있으면 ppo). 실행 연결은 `tools.submit-decision` → `ExecContext.rl_sizer`(`shadow.load`: `ml.yaml rl_sizer.enabled` ∧ 승격 모델) 하나뿐이고, executor 는 **`env == "paper"` ∧ BUY/ADD ∧ 손절 아님** 일 때만 관측(피처 스토어 최신 행 + 포지션·NAV 이력)·제안·`rl_shadow` 기록(결정·계좌당 1행)을 하며 `mode: apply` 면 그 계좌의 `target_weight` 만 바꾼다(게이트 상한·규칙은 그대로, reasons 앞에 "RL 사이저 적용"). 실전 계좌·HOLD·SELL 은 RL 코드를 거치지 않는다. 관측·기록 실패는 경고 후 RL 없이 판정한다.

**번들(PyInstaller frozen) 분기는 `platform/bundle.py` 에만 둔다.** `is_frozen`·`bundle_root`(실행파일 폴더 = TRADER_HOME)·`resource_dir`(`_internal/`)·`tool_command`(frozen `trader tool`, 개발 `python -m trader tool`)·`tool_bin_dir`·`daemon_argv`·`first_run_init`. 세션의 `--allowedTools` 와 오케스트레이터 프롬프트는 `bundle.tool_command()` 로 같은 문자열을 쓰고(`registry.orchestrator_prompt` 가 md 의 `python -m trader tool` 을 치환), 웹 dist·에이전트 md 는 `paths.web_dist()`·`paths.agents_dir()` 로만 찾는다. `templates/config/*.yaml` 은 `config/*.yaml` 의 사본(계좌번호는 `"00000000"`)이라 **config 를 바꾸면 templates 도 같이 바꾼다**. `secrets/`·`state/` 는 번들에 넣지 않는다. `claude` CLI 는 번들하지 않는다(구독 인증). ### 보완 5차 — 실행 키·예상 포트폴리오·승인 재판정 (O8·O10·O12, 원장 v21)
- **실행 키(O8).** 원장 v21 `exec_keys(key PRIMARY KEY, created_at, order_id, approval_id, sent_at)`. `_execute_account` 는 판정이 주문·승인 요청으로 이어질 때(승인·mode≠off·dry-run 아님·일시정지 아님) `has_open_order_or_approval` 뒤에 `repo.claim_exec_key` 로 INSERT 하고, 살아 있는 키가 있으면 주문 없이 "다른 프로세스가 … 실행 키 선점됨" 거부로 판정을 남긴다 — 중복 확인과 주문 사이의 경합(데몬 재평가 ↔ 수동 재실행)을 닫는다. 키: 결정 주문 `결정id|계좌|방향|주문단계`, 손절 `stop|계좌|종목|운영일`, 결정 행 없는 주문(단타·리밸런스) `주문단계|계좌|종목|방향|운영일`. 수명: `_place` 가 브로커 호출 직전 `sent_at`, 거부·실패면 `release_exec_key`(KIS 에 주문 없음 → 재시도), 접수·unknown 은 `order_id` 로 묶는다. approve 모드는 요청 때 키를 잡아 `approval_id` 로 묶고 `order_json.exec_key` 로 승인 실행(`approve` → `_place`)이 이어 쓴다. 이미 있는 키는 조건부 UPDATE 로 넘겨받는다: 묶인 주문이 죽었거나(취소·만료 — US 손절 지정가 취소 뒤 재손절), 보내지도 승인 요청도 없이 `EXEC_KEY_STALE`(10분) 지났거나(선점 뒤 프로세스 사망), 묶인 승인이 거절·만료·실패로 닫혔을 때. 보냈는데 주문 행이 없는 키(접수 뒤 기록 실패)는 넘겨받지 않는다(수동 대조). **남은 한계**: 단계가 다른 동시 실행(`50_` ↔ `51_r1`)과 다른 종목의 동시 판정(종목 수·섹터 합계)은 키가 달라 막지 못한다 — 계좌 단위 직렬화가 필요하며 데몬은 큐·heavy 락으로 대부분 순차다. 체크포인트 임시파일은 pid·스레드 접미사(데몬 스레드끼리 겹침 방지).
- **예상 포트폴리오(O10).** `build_portfolio` 가 `repo.pending_buy_amounts`(오늘 체결 전 BUY 주문 accepted·partial·unknown + 만료 전 pending BUY 승인의 종목별 금액)를 `Portfolio.pending_buys` 로 넘기고, `rules.evaluate` 의 종목 수·섹터(`max_sector_pct`)·테마(`_theme_rejections`) 합계는 `Portfolio.exposure()`(일반 보유 평가 + 체결 전 매수, 헤지 ETF 제외)로 본다. 현금은 기존대로 `today_order_amount` 만 차감(이중 차감 없음 — `today_order_amount` 와 `pending_buy_amounts` 는 같은 `_buy_amounts_today` 를 쓴다). partial 은 주문 전체 금액이라 체결분이 보유와 겹쳐 보수적으로 센다. 헤지·손절은 BUY 분기 밖이라 무관, 단타는 종목 수·섹터는 보고 테마는 면제(기존과 같다).
- **승인 재판정(O12).** `executor.approve` 는 BUY(헤지 결정 제외)일 때 조건부 UPDATE 직전 `_approval_recheck`: 국면 bear ∧ 전략가 기울기 ≤ 0, 또는 잔고 NAV 의 전일 대비 손익 ≤ `daily_loss_stop_pct` 면 주문 없이 승인 `expired` + 사유. 수량은 다시 계산하지 않는다(전체 게이트는 요청 때 1회). 잔고 조회 실패는 판정 불가로 요청을 pending 으로 둔다. SELL 은 재판정하지 않는다. 일시정지는 기존대로 `approve` 첫머리에서 거부하고 요청은 pending 유지(재개 뒤 30분 안이면 승인 가능).

## 전체 검토 보완 4차 묶음 A — 프로세스·성능 (2026-10-26)
- **빠른 대기열 레인(P2).** `jobs.FAST_KINDS` = `LIGHT_KINDS` + `reevaluate`. 데몬은 `job_queue`(heavy 락을 잡을 때만, 모든 kind) 옆에 `job_queue_fast`(같은 10초 간격, heavy 락 없이 `claim_next(kinds=FAST_KINDS)`)를 돌린다 — 백필·scan_analyze 가 몇십 분 heavy 락을 쥐어도 손절 재평가·체결 동기화가 같은 틱에 나간다. 두 틱 모두 `max_instances` 경고를 삼킨다.
- **데몬 잠금(P4).** `daemon.Lock.acquire` 는 먼저 `daemon.lock.os` 에 **수명 동안 쥐는 OS 파일 잠금**(`platform/filelock.try_hold`, fcntl/msvcrt — 핸들 단위라 같은 프로세스의 두 번째 Lock 도 막힘)을 잡고, 그다음 기존 pid 파일 검사(살아 있는 pid·방금 생긴 빈 파일 거부)를 한다. 죽은 잠금 인수 판단을 두 프로세스가 동시에 해도 OS 잠금이 하나만 통과시킨다. pid 파일은 `heartbeat.read_status` 표시·생존 판정용으로 그대로 쓴다.
- **수집 기한(P7).** `build_inputs` 의 세 절은 시작부터 `SECTION_TIMEOUT_S` 공통 기한, 넘으면 오류 절(`timeout after …`)로 적고 풀은 `shutdown(wait=False, cancel_futures=True)` — 예전 `with` 풀은 닫힐 때 멈춘 스레드를 끝까지 기다렸다.
- **heavy 대기(P8).** `DaemonDeps.heavy_wanted` 는 `HeavyWanted` 카운터(enter/leave/is_set) — cron 둘이 기다릴 때 먼저 끝난 쪽이 양보 요청을 지우지 않는다.
- **derive 락(P9).** `features.rederive` 는 날짜 파일마다 스토어 락을 잡고 놓으며 진행 콜백은 락 밖에서 부른다(콜백이 heavy 락을 양보하는 사이 reflect 스냅샷이 LockTimeout 나던 문제).
- **파일 교체(P11).** 원자 교체는 `platform/fsutil.atomic_replace`(PermissionError 지수 백오프 재시도, Windows 공유 위반) — 피처 날짜 파일·체크포인트·하트비트·watchdog·KIS 토큰 캐시. `features.read_part(strict=True)` 는 OSError(다른 프로세스가 연 파일)를 올려 `write_rows` 가 새 행만으로 날짜 파일을 덮어쓰지 않게 하고, 파싱 오류(진짜 파손)만 None.
- **보존 정리(P12).** reflect 잡 끝 `ops/retention.prune(keep_days=settings.retention_days, 기본 120)`: `state/runs/<날짜>` 폴더, 키에 날짜가 든 control 행, 끝난 `job_requests`, 세션 행이 없는 `runs`(세션 runs 는 readiness 운영일 집계라 유지), `llm_rate_limits`. 결정·주문·체결·메모리·섀도 원장은 지우지 않는다.
- **레이트 스토어(P13).** `SharedRateLimiter` 는 스레드 로컬 SQLite 연결을 재사용하고 DDL 은 인스턴스당 1회(잠금 오류 중 열린 트랜잭션은 ROLLBACK, 실패하면 연결을 새로 연다).
- **뉴스 인덱스.** 원장 v22 `ix_news_market_received ON news_items(market, received_at)`.

- **업종 자동 분류(`scan/sector_suggest.auto_classify`·`resolver`)**: 잔고를 관측할 때(위 두 경로) `sectors.yaml` 에 없는 보유 종목만 KIS 업종명 → `*_industry_to_sector` 로 대분류, 업종이 없고 이름이 국내 ETF 상표면 `ETF`. 결과는 `state/cache/sector_auto.json`(미분류도 캐시해 재조회 안 함, 조회 실패는 캐시 안 함). 웹 섹터 비중(`/api/portfolio`·`/overview`)은 yaml → 자동 캐시 순이고 자동 행에 `auto: true`('자동' 꼬리표). **리스크 게이트의 업종 상한은 계속 `sectors.yaml` 만 본다**(자동 분류는 표시용).
- **Claude 사용량 확인(`orchestrator/quick.probe_usage`)**: 데몬 interval 잡 `usage_probe`(`llm.usage_probe.interval_min` 30분)가 haiku 단발 `claude -p`(도구 없음, `quick._spawn` 공용) 1회의 `rate_limit_event` 를 `llm_rate_limits(source='probe')` 로 남긴다. 최근 `skip_if_recent_min`(5분) 안에 관측이 있거나 감속 hard 이상이면 쉰다, FAKE 면 호출 없음, `agent_calls.agent='usage_probe'` 라 세션 상한 밖. `usage._ledger_observation` 의 `source` 는 가장 최근 행의 출처(session|probe).
- **화면**: 상단 바 `Clock`(1초, KST 초 단위 + 뉴욕 시각 + 장 상태, `useNow`), 용어 `Term` 은 클릭 팝오버(button + `position: fixed`, Esc·바깥 클릭·스크롤로 닫힘, 한 번에 하나, `termPopover.popoverPosition`), 사용량은 초기화 시각 KST 절대 표기 + 남은 시간(지나도 '초기화됨' 으로 남음, 경과는 클라이언트 시계), 대시보드 합산·시세표·계좌 상세가 같은 실시간 시세(`useLiveQuotes` 시장별 1회, 장 밖 1분 재확인)로 순자산·평가손익을 갱신(`overview.liveSummary`), 분봉 차트는 장중 1분마다. 오른쪽 열 순서: 성과 → Claude 사용량 → 모델 → 작업 대기열 → 데몬 잡(접힘).
