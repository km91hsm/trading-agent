# SaveTicker 브라우저 수집 설계

사용자 승인: 2026-10-25 전체 수집 진행 및 전용 파일에 계정 정보 저장·자동 로그인 요청.

## 범위
- 뉴스 출처 탭과 카테고리별 목록·상세, 커뮤니티 전체·종목 글과 댓글, 커뮤니티 지수·상승·하락, 증시 거래대금·상승·하락, 캘린더 전체 일정과 발표 수치.
- 전체는 사이트가 표시한 범위다. 무한한 과거를 약속하지 않는다. 최초 캘린더 범위는 지난달~앞으로 3개월. 목록 스크롤 한도·상세 처리 한도·로딩 실패는 partial 로 표시한다.
- 로그인된 렌더링 DOM만 수집. 비공개 API·보호 우회·사용자 게시·관심종목 변경·주문 실행 없음.

## 선택한 방식
1. Codex가 매번 읽기: 검증에는 유용하지만 상시 실행과 초 단위 주기를 보장할 수 없다.
2. Python + Playwright 전용 브라우저: 선택. 화면 선택자만 쓰고 옵션 의존성으로 격리, 계정은 secrets/saveticker.env, 비밀번호·쿠키·로그인 화면을 결과에 넣지 않는다.
3. 직접 HTTP: 현재 403이므로 제외. 다른 뉴스 소스 설정은 변경하지 않는다.

## 저장·운영 계약
- state/external/saveticker/ 아래 SQLite를 원본으로 변경 이력 유지. JSONL은 UTC 날짜·종류별 변경분, latest/<stream>.json은 최신 화면 결과, status.json은 스트림별 마지막 시도·성공·오류·partial·지연.
- 원자적 파일 교체. 재시작·다중 탭 중복 억제. 같은 항목의 수정·조회수·순위 변동은 새 revision. 상대시각만 변하면 수정으로 보지 않는다.
- 수집 시각 UTC, 화면 표시는 원문과 별도 보존. 브라우저 timezone은 Asia/Seoul로 고정. 시각 없는 글은 published_at=null. 캘린더 예정 시각과 발표값을 알게 된 시각을 구분한다.
- 핵심 전체 뉴스·커뮤니티·실시간 순위 30초, 정규장 순위·출처/카테고리 전체 검증·캘린더 300초 목표. 핵심 목록 우선 + 8회마다 배경 수집 1회를 처리한다. 실제 소요 시간·초과 지연을 기록하며 성공한 오래된 파일을 최신으로 위장하지 않는다. 소스 탐색 동작 간 2초 이상.
- 로그인 실패는 결과를 비우지 않고 auth_required로 보고, 제한된 재시도 후 종료. 예외 메시지·브라우저 trace·쿠키·폼 값은 저장하지 않는다.
- 독립 CLI로 실행. 기존 거래 데몬·리스크·주문을 변경하지 않는다. 분석 연결은 원본 시각·수신 시각을 필터하는 읽기 CLI로 제공한다.

## 검증
네트워크 없는 저장·재시작·오류·타임존·파서·CLI 테스트. 실제 DOM 선택자는 Codex 브라우저로 교차 검증. 별도 브라우저 라이브 검증과 계속 실행 여부는 결과에 구분 보고한다.

## 실행에서 확정한 사항
- 일반 창 브라우저에서는 자동 로그인·36개 화면 수집이 성공했으나 headless의 /profile은 HTTP 403이었다. 기본은 headed이며 접근 거절은 우회하지 않고 종료한다.
- 종일·시각 미정 일정도 scheduled_date로 보존한다.
- 최초 화면에는 사이드 패널 순위가 섞일 수 있어 가장 가까운 순위 영역으로 선택자를 제한한다.
- 추가 데이터는 별도 외부 서비스에 가입하지 않고 원본 시각·수치·변경 이력부터 확보한다.
