# Phase 7 ML 1단계 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 피처 스토어로 5거래일 수익률 3분류 퀀트 모델을 워크포워드로 학습·평가하고, 승격 기준을 통과한 모델만 `05_quant.json`(트레이더 입력)과 scan 랭킹에 반영하며, 레지스트리·UI 에서 성능과 피처 중요도를 볼 수 있게 한다.

**Architecture:** `ml/dataset`(피처 적재·라벨·엠바고) → `ml/walkforward`(비중첩 폴드) → `ml/models/quant`(GBDT 3분류, 평가) → `ml/registry`(버전·메타·승격) → `ml/train`(파이프라인) 순의 순수 파이썬 층. 투입은 두 곳뿐이다: `tool collect` 가 `00_inputs` 직후 승격 모델로 `05_quant` 체크포인트를 쓰고 트레이더 묶음 `context.quant` 로 전달, `scan` 의 `rank_fn` 이 P(상승) 으로 정렬한다. 모델 백엔드는 scikit-learn `HistGradientBoostingClassifier`(LightGBM 은 macOS 에서 `libomp` 가 필요해 선택 사항; `lightgbm` 이 import 되면 그것을 쓴다).

**Tech Stack:** scikit-learn 1.x(HistGradientBoostingClassifier, permutation_importance), pandas/pyarrow(피처 스토어), joblib(모델 직렬화), 기존 FastAPI·React.

**Spec:** `docs/superpowers/specs/2026-10-09-trading-agent-design.md` §9.1(퀀트 예측), §9.2(랭커), §9.5(학습 잡·레지스트리), §3.4(피처 스토어), §1.4(05_quant 데이터 흐름), §11 Phase 7 행, §13.

## Global Constraints

- Phase 0~6 규칙 전부(CLAUDE.md). 금액 `Decimal`, 시각 UTC, 한국어 문구, 라인 100자.
- **라벨**: `ml.yaml` `label.horizon_days`(5) 뒤 종가 수익률을 `thresholds.up`(+2%) 이상 → `up`, `thresholds.down`(−2%) 이하 → `down`, 그 사이 `flat`. 라벨에 쓰인 미래 봉이 없는 마지막 `horizon_days` 행은 라벨 없음(학습·평가 제외).
- **라벨 엠바고**: 학습 구간의 마지막 날짜는 `test_start − (horizon_days + embargo_days)` 보다 작아야 한다(`embargo_days` 5). 테스트 창끼리는 겹치지 않는다(비중첩).
- **워크포워드**: `train.walk_forward_folds`(6) 개의 비중첩 테스트 창, 학습은 그 이전 전부(확장 창). 각 폴드마다 정확도와 기준선(최빈 라벨 정확도), 알파(예측 `up` 행의 평균 5일 수익 − 전체 평균)를 기록한다.
- **승격**: 폴드 평균 정확도 ≥ `promote_min_accuracy`(0.40) **그리고** 폴드 평균 알파 ≥ `promote_min_alpha`(0.0) 일 때만 `promoted: true`. 승격 모델이 없으면 `05_quant` 는 쓰지 않고 scan 은 정량 점수로 정렬한다(파이프라인이 ML 없이도 돈다).
- **룩어헤드 금지**: 피처 행 `date` 의 값만 쓴다. 라벨은 `date` 이후 봉으로만 만든다. 역검증 테스트(라벨 섞기·미래 열 주입)가 필수다.
- 모델 파일은 `state/models/<name>/<YYYYMMDD_HHMMSS>/model.joblib` + `meta.json`(학습 구간·행 수·폴드 지표·피처 목록·중요도·promoted·promote_reason). 파일명에 `:` 금지.
- 의존성은 Windows 휠이 있는 것만(scikit-learn·joblib). `lightgbm` 은 필수 의존성에서 제외한다.
- `05_quant` 체크포인트 스키마는 `agents/schemas.QuantReport`(role `"quant"`)로 검증한다. 트레이더·오케스트레이터 md 는 `context.quant` 가 null 일 수 있음을 명시한다.
- 테스트는 합성 피처(신호가 있는/없는)로 결정적으로(random_state=0) 돌리고, 실제 `state/features` 는 Task 6 실기에서만 쓴다.

## Review Focus

1. 테스트 창의 날짜가 학습 창 라벨의 미래 봉과 겹치면 안 된다(라벨 누출). → Task 2 `test_folds_non_overlapping_and_embargoed`, `test_train_label_windows_end_before_test_start`.
2. 라벨을 섞으면 정확도가 우연 수준이어야 한다(피처에 미래 정보가 섞이지 않았다는 역검증). → Task 2 `test_shuffled_labels_give_chance_accuracy`, Task 3 `test_future_leak_column_is_rejected`.
3. 승격 기준에 못 미친 모델은 `05_quant` 도, scan 랭킹도 바꾸면 안 된다. → Task 3 `test_not_promoted_when_below_threshold`, Task 4 `test_collect_skips_quant_without_promoted_model`, `test_rank_fn_falls_back_without_model`.
4. 피처 행이 100개 미만이거나 라벨이 한 종류뿐이면 학습은 실패가 아니라 "데이터 부족" 으로 끝나야 한다. → Task 3 `test_train_reports_insufficient_data`.
5. 피처 열이 모델 학습 때와 달라진(열 추가·누락) 스냅샷으로 예측하면 누락 열은 NaN 으로 채우고 추가 열은 무시해야 한다. → Task 4 `test_predict_aligns_feature_columns`.

- `train.train_quant(cfg: MlConfig, *, state=None, market: str | None = None, now=..., min_rows: int = 100) -> dict{status: "trained"|"insufficient_data", version, metrics, promoted, promote_reason, rows, features}`: load_all → make_labels → (행 < min_rows 또는 라벨 종류 < 2 → insufficient_data) → evaluate_walkforward → 전체 라벨 행으로 최종 fit → importances(마지막 폴드 테스트) → save → 승격 판정(`accuracy ≥ promote_min_accuracy and alpha ≥ promote_min_alpha`) → promote.
- 합성 데이터 헬퍼 `tests/helpers_ml.py: synthetic_features(n_tickers, n_days, *, signal: bool, seed=0) -> DataFrame`(`signal=True` 면 `roc_10` 이 미래 수익과 양의 상관이 되도록 생성).
