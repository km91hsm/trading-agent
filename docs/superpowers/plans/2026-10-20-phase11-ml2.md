# Phase 11 ML 2단계 (순위 기준 승격·횡단면 라벨·유니버스 확대) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 퀀트 모델의 문제 정의를 "절대 ±2% 3분류 정확도" 에서 "횡단면 상대 순위 + 상위 N 알파" 로 바꾸고 유니버스를 KOSPI 200·US 대형주 50 으로 넓혀, 승격 기준을 낮추지 않고도 신호가 있으면 승격될 수 있게 한다.

**Architecture:** 라벨러(`ml/dataset.make_labels`)에 `relative_tercile` 모드(같은 날·같은 시장 안 `fwd_return` 삼분위, 기준선 1/3 고정), 승격 판정(`ml/train.promotion_decision`)에 `alpha` 지표 모드(폴드별 상위 N 알파가 양인 비율 + 평균 알파 ≥ 왕복비용)를 추가한다. 설정은 `ml.yaml` 로만 바뀌고 기본값은 기존 동작(absolute·accuracy)을 유지한다. 유니버스는 `trader universe check` 로 KIS 시세가 실제로 오는 코드만 남긴다. 승격 안 되면 파이프라인은 지금처럼 ML 없이 돈다.

**Tech Stack:** pandas, scikit-learn(sklearn 백엔드 유지), pydantic 설정.

**Spec:** `docs/superpowers/specs/2026-10-09-trading-agent-design.md` §9.1(퀀트 모델·워크포워드·승격), §5.1(scan 랭킹 투입 지점). 추천 근거는 2026-10-20 대화(3년 백필 뒤 KR 0.343/0.354·US 0.385/0.399 미승격).

## Global Constraints
- 기본 설정(`mode: absolute`, `promote_metric: accuracy`)에서 기존 테스트·동작 불변. 승격 기준 완화 금지(알파 기준은 왕복비용 이상, 폴드 다수 양).
- 라벨 누출 방지 계약 유지: `fwd_date`·엠바고·`walkforward.split` 그대로.
- `templates/config/*.yaml` 은 `config/*.yaml` 과 같아야 한다(패리티 테스트). 유니버스 변경 시 둘 다.
- `uv run pytest`·`uv run ruff check src tests` 0건.

## Review Focus
- 같은 날 종목이 3개 미만인 날(백필 초기·휴장 섞임)의 상대 라벨은 NaN 이어야 한다 (Task 1 테스트).
- 알파 모드에서 `up_count`(상위 예측 수) 기준은 유지돼 "전부 중립" 모델이 승격되지 않는가 (Task 2 테스트).
- 유니버스 확대 뒤 scan 의 `latest_rows(tickers=)` 조기 종료가 200종목에서도 1초 안쪽인가 (Task 3 실측).
- 상대 라벨은 시장별로 매겨야 한다(KR·US 를 섞어 학습하는 `--market` 없음 호출에서 날짜만으로 묶지 않는가) (Task 1 테스트).
- US 유니버스의 거래소 코드가 틀리면 수집·백필이 조용히 빈 결과를 내므로 `universe check` 가 그것을 잡는가 (Task 3 테스트).

### Task 2: 알파 기준 승격
**Files:** Modify `src/trader/config.py`(`QuantModelCfg.promote_metric`, `promote_min_positive_folds`), `src/trader/ml/train.py:promotion_decision`, `src/trader/cli.py`(`ml train --horizon` 실험 옵션); Test `tests/ml/test_train.py`, `tests/test_config_ml.py`, `tests/test_cli_ml.py`.
**Interfaces:** `QuantModelCfg.promote_metric: Literal["accuracy","alpha"] = "accuracy"`, `promote_min_positive_folds: float = 0.67`. `promotion_decision(metrics, cfg) -> tuple[bool, str]`: alpha 모드 = `metrics["alpha"] ≥ promote_min_alpha` ∧ `(alpha>0 폴드 수 / 폴드 수) ≥ promote_min_positive_folds` ∧ 모든 폴드 `up_count ≥ min_up_predictions`; 사유 문자열은 한국어로 미달 항목 전부. `ml train --horizon N` 은 `cfg.label.horizon_days` 를 덮어쓴다(설정 파일 불변).
- [ ] Step 1 실패 테스트: `test_promotion_alpha_mode_requires_mean_and_fold_fraction`(평균 0.004, 폴드 5/6 양 → 승격; 3/6 → 미승격 사유에 "폴드"), `test_promotion_alpha_mode_still_requires_up_predictions`, `test_promotion_accuracy_mode_unchanged`, `test_cli_ml_train_horizon_override`.
- [ ] Step 2 RED → Step 3 구현 → Step 4 PASS → Step 5 커밋 `feat(ml): 알파 기준 승격 모드·--horizon`

### Task 3: 유니버스 확대 + `trader universe check`
