# Phase 5 웹 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 로컬 브라우저에서 계좌별 포트폴리오·오늘의 실행 산출물·주문/승인·차트·설정/제어를 보고, 토큰이 있을 때만 제어(승인·모드·일시정지)할 수 있는 FastAPI + React 웹 UI.

**Architecture:** `src/trader/web/` 의 FastAPI 앱이 원장(SQLite)·체크포인트(`state/runs`)·KIS 시세를 읽어 JSON API 를 내고 `web/dist`(Vite 빌드)를 정적으로 서빙한다. 조회 API 는 전부 `account_id` 필터(모의·실전 분리), 제어 API 는 `Authorization: Bearer <WEB_TOKEN>` 으로만 열린다. 제어는 Phase 4 의 `executor.approve/reject`·`control.set_account_mode` 를 그대로 호출해 규칙(만료·1회·실전 confirm)을 재사용한다. 실시간은 SSE 1개(`/api/events`, 원장 카운터 폴링).

**Tech Stack:** FastAPI, uvicorn, Starlette StreamingResponse(SSE), fastapi TestClient(httpx); React 18 + Vite 7 + TypeScript, react-router-dom, lightweight-charts 5, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-09-trading-agent-design.md` §8(웹 UI), §1.2(`web` 명령), §1.3(`src/trader/web/`, `web/`), §6.2(승인), §11 Phase 5 행, §13(TestClient·Vitest).

## Global Constraints

- Phase 0~4 규칙 전부(CLAUDE.md). 금액 `Decimal` → JSON 은 문자열, 시각 UTC ISO. 사용자 대면 문구 한국어. 라인 100자.
- 바인드 `127.0.0.1:8787`(`settings.web.bind/port`). 조회 API 토큰 없음, **제어 API 는 `Authorization: Bearer <WEB_TOKEN>`**(`secrets.WEB_TOKEN`). 토큰 미설정이면 제어 API 는 전부 401(열리지 않음).
- **모든 조회가 `account_id` 로 거른다.** 계좌 단위 엔드포인트는 `account_id` 가 없으면 400. 전체 대시보드만 계좌 합산.
- 주문·모드 변경은 Phase 4 함수(`executor.approve/reject`, `control.set_account_mode`)를 통해서만. 웹이 KIS 주문 API 를 직접 부르지 않는다. 실전 `auto` 전환은 body `confirm: "LIVE"` 가 있어야 하며 없으면 400.
- 웹 서버는 KIS 를 시세(차트 일봉)와 `portfolio refresh` 에만 호출한다(레이트리밋 고려, 조회 페이지는 원장 스냅샷).
- 체크포인트 읽기는 `run_store`(`ticker`·`market`·`stage` 형식 검증) 로만. 경로 파라미터는 `tools._validate_ids` 로 검증해 경로 탈출을 막는다.
- `web/dist/`·`web/node_modules/` 는 gitignore. `trader web` 은 dist 가 없으면 안내 HTML 을 돌려준다. Node 는 빌드 시에만 필요(런타임 파이썬 전용).
- 테스트는 `TestClient` + `tmp_path` 프로젝트(`project` 픽스처), KIS 는 `FakeMarket/FakeBroker`, 네트워크 없음. Vitest 는 api 헬퍼 1개 이상.

## Review Focus

1. 제어 API 에 토큰이 없거나 틀리면 401 이어야 하고, `WEB_TOKEN` 미설정 시에도 열리면 안 된다 → Task 1 `test_control_requires_token`, `test_control_unavailable_without_configured_token`.
2. 주문·승인·포지션 조회에 `account_id` 가 없으면 400 이고, 모의 계좌 주문이 실전 계좌 응답에 나오면 안 된다 → Task 2 `test_orders_isolated_per_account`, `test_account_id_required`.
3. 같은 승인을 웹에서 두 번 승인하면 두 번째는 409 이고 주문은 1건이어야 한다 → Task 4 `test_web_approve_twice_conflict`.
4. 실전 계좌를 웹에서 `auto` 로 바꾸려면 `confirm: "LIVE"` 가 있어야 하고 없으면 400 + 모드 불변 → Task 4 `test_web_mode_real_auto_requires_confirm`.
5. 체크포인트 조회의 `ticker`/`stage` 에 `../` 가 오면 400 이어야 한다 → Task 3 `test_checkpoint_path_traversal_rejected`.

### Task 4: control 라우터(승인·모드·일시정지) + SSE

**Files:**
- Create: `src/trader/web/routers/control.py`(Task 1 의 pause 포함해 완성), `src/trader/web/sse.py`
- Test: `tests/web/test_control_sse.py`

**Interfaces:**
- 전부 `Depends(require_token)`. `POST /api/control/approve {approval_id}` → `executor.approve(ExecContext(deps…), id)`; `ok` 면 200 `{ok, order}`, 이미 처리·만료·없음이면 409 `{detail}`. `POST /api/control/reject {approval_id}` 동일. `POST /api/control/mode {account_id, mode, confirm?}` → `control.set_account_mode`; `ConfirmationRequired` → 400, 모르는 계좌·모드 → 400; 200 `{account_id, mode}`. `POST /api/control/pause|resume` → `{ok, paused}`. 웹의 `ExecContext.notifier` 는 `make_notifier(secrets)`(deps 에 `notifier` 필드 추가; 테스트는 기록용 가짜).
