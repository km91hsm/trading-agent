# SaveTicker Chrome 수집 확장

일반 Chrome의 로그인된 SaveTicker 화면을 네 개의 전용 탭에서 읽어 Native host `com.trader.saveticker`로 전달합니다. 확장 ID는 `gfchfnjghmjiidifohjglpodaakdphho`입니다. 수집은 수집 시작 시 한 번 표시하는 전용 Chrome 창에서 네 lane의 탭을 차례대로 활성화하여 진행합니다. 사용자 탭은 URL이 같아도 가져오지 않습니다. 확장 storage의 임의 소유 token과 URL 마커가 모두 일치하는 탭만 복구합니다.

확장 설치·호스트 등록·backend 변경은 운영자의 최종 승인 후 별도 설치 명령으로 진행합니다. 이 디렉터리를 작성하는 것으로 Chrome에 설치되거나 사용자 프로필이 바뀌지 않습니다.

권한은 alarms/storage/nativeMessaging/downloads와 `https://www.saveticker.com/*`입니다. 쿠키·로그인 값·요청 헤더를 읽지 않고 자동 로그인을 하지 않습니다. MAIN world 요청 관찰은 사용하지 않으며 매 작업에서 실제 선택 상태를 확인한 새 DOM만 보냅니다. DOM의 스크립트·폼·입력·메뉴·탐색 영역을 제거합니다. 가상 목록을 두 번 스크롤한 수집과 본문 확인이 불가능한 항목은 **partial**로 남습니다.

호스트 hello의 전체 plan과 수집 한도를 사용합니다. 30초 알람을 복구 수단으로 유지하며 연결 중에는 5초 뒤 다음 due 작업을 점검합니다. 기본 작업 한도는 스크롤 두 번, 뉴스 본문 두 건, 리포트 두 건이며 PDF는 전역 한 건씩 직렬 처리합니다. 정규장/실시간 선택은 실제 aria 속성, 월은 화면 레이블에서 확인합니다. 선택 증거가 없으면 오류로 남기고 다른 스트림으로 저장하지 않습니다. 본문은 dialog 또는 실제 제목과 div.gap-6.p-6 본문을 포함한 조상 영역에서 읽습니다. 닫기 버튼 또는 Escape 이후 상세가 닫히고 목록이 남는지 확인하며, 닫힘을 확인할 수 없으면 성공으로 저장하지 않습니다.

시작은 enabled를 저장하고 30초 알람을 설정합니다. 인증·보안 확인은 사이트 전체 네 lane의 중지 상태를 저장하며 worker 재시작 후에도 유지됩니다. 사용자가 전용 탭에서 확인 후 **직접 확인 후 재개**를 눌러야 다시 확인합니다. 수집 중지는 알람·Native 연결·PDF 연결을 종료하며 재연결하지 않습니다. 전용 탭은 사용자가 확인할 수 있게 남겨 둡니다. 절전이나 Chrome 종료 중에는 수집할 수 없습니다.

PDF 클릭 전에 호스트의 일회 ticket과 32hex nonce를 발급합니다. 정적 MAIN 도우미는 소유가 확인된 뉴스 리포트 버튼이 nonce로 표시된 경우에만 최대 15초 동안 DOM 앵커 click과 합성 MouseEvent의 dispatchEvent를 관찰합니다. 정확한 same-origin blob 앵커(분리된 앵커 포함)의 원래 click만 억제하고 URL을 전달하며, 해당 blob의 요청된 revoke만 release/만료까지 지연합니다. 여러 후보·사용자 조작·이동·만료는 연결을 취소합니다. 모든 호출에서 실제 시각의 만료를 확인하므로 숨겨진 페이지의 타이머에만 의존하지 않습니다.

확장은 관찰된 blob URL로 Chrome downloads.download를 호출하고 반환된 downloadId만 연결합니다. 발급 파일명을 API에 직접 지정하며 다른 다운로드의 파일명을 변경하지 않습니다. 반환 전에 완료된 경우도 ID 조회로 확인합니다. 실제 파일명이 `SaveTicker/<발급명>`과 다르면 Native 저장을 요청하지 않습니다. Native의 ticket·실제 PDF·경로 검증은 그대로 유지합니다. 도우미 준비 실패·주소 미확인·Chrome blob 다운로드 실패·Native 검증 실패는 popup의 고정 상태로 표시하며 partial을 유지합니다. 브라우저가 페이지 blob의 확장 다운로드를 허용하는지는 설치 후 실제 Chrome에서 확인해야 합니다.

테스트: 저장소에서 `node --test extensions/saveticker/tests/*.test.js`. DOM 테스트는 기존 `web/node_modules/jsdom`을 사용합니다 (`cd web && npm ci` 후 실행). 합성 UI·가짜 Chrome/Native 이벤트만 사용하며 개인 브라우저를 제어하지 않습니다. 실제 사이트의 새 UI가 선택 속성을 노출하지 않으면 안전하게 실패할 수 있습니다. 설치 후 로그인된 실제 Chrome에서 UI 선택·다운로드·재시작을 별도로 확인해야 합니다.

1.0.1은 Chrome 새 탭의 `url`이 아직 없을 때 `pendingUrl`을 확인하고, 실패한 작업을 오류 캡처로 종료합니다. 팝업은 설치 버전과 실제 worker 실행 버전을 함께 표시하여 확장 관리 화면의 다시 로드가 적용됐는지 확인할 수 있습니다. 커뮤니티의 선택된 버튼 CSS와 비활성 정규장 체크박스를 읽습니다. 사이트가 정확히 “지금은 실시간과 정규장 기준이 같아요”라고 안내한 비활성 체크 상태에서만 기준 동등성을 전달하며, 실제 체크값과 요청 기준을 따로 보존합니다.

전용 창은 저장된 window ID만 믿지 않고 해당 창의 모든 탭이 소유 token과 일치하는지 확인하여 재사용합니다. 일반 탭이 섞였으면 소유 탭만 새 전용 창으로 옮기며 일반 탭은 이동하거나 닫지 않습니다. 창이 최소화되면 자동으로 복원하거나 포커스하지 않고 수집 상태를 일시 정지로 남깁니다. 사용자가 전용 창을 복원하면 다음 주기에 다시 확인합니다.

프로필 표시 후에도 소스·카테고리·월별 조작부의 준비를 총14초까지 기다리며 실제 선택을 두 번까지만 시도합니다. 달력 이동은 두 시도를 합쳐26회로 제한합니다. 인증·보안 화면에서는 이 시도를 중단합니다. 일반 수집 오류는 정상 주기보다 빠르게 재시도하지 않습니다. 기본 대기는 정상 주기와60초 중 큰 값이며 반복 실패 시 정상 주기와15분 중 큰 값을 상한으로 지수 대기합니다. 예약 시각과 실패 횟수를 로컬 저장하고 현재 plan과 검증해 worker 재시작 후 복원합니다. 실제 시도 시각을 보존하여 아직 수집하지 않은 월/리포트가 먼저 진행됩니다.

페이지의 지연 초기화를 위해 새 전용 창을 만들 때, 사용자가 시작·재개할 때, Chrome 시작 시에만 소유가 확인된 전용 창을 한 번 표시합니다. 일반 수집 주기나 기존 창을 재사용하는 MV3 worker 재시작에서는 다시 포커스하지 않습니다. 최소화한 창은 자동 복원하지 않습니다. 수집 창이 표시되고 완전히 가려지지 않은 상태를 유지해야 하며, Chrome을 숨기거나 창을 가리면 페이지 초기화와 타이머가 지연될 수 있습니다.

화면 조작·스크롤·본문 대기와 PDF 관찰 시간은 숨겨진 페이지의 타이머 대신 Native 연결을 유지하는 확장 worker의 고정2초 응답을 기다립니다. 동일 확장의 정확한 소유 탭/token만 요청할 수 있고 탭마다 대기는 한 개로 제한됩니다. 중지·연결 해제 시 대기를 취소합니다. 실제 Chrome에서 worker 응답이 없으면 페이지 타이머로 조용히 우회하지 않고 오류로 남깁니다.

뉴스 소스 선택이 주소의 소유 마커를 제거하는 경우, 이미 소유가 증명된 탭의 현재 발급 작업 중에만 마커를 복구할 수 있습니다. hash가 비어 있고 같은 뉴스 경로의 전체 뉴스(빈 query) 또는 SAVE 리포트(query가 정확히 label_group=7)인 경우만 허용합니다. 다른 hash·query·경로·origin 또는 진행 중 작업이 없는 탭은 복구하지 않습니다. 이 예외는 수집부터 PDF 버튼 처리까지 유지되며 작업 종료·중지·연결 해제 때 폐기됩니다.

뉴스 목록은 실제 #news-tabpanel 카드만 프레임당100개·512KiB, 세 프레임까지 전송합니다. 넘치는 카드는 건너뛰며 다른 카드 수집을 유지합니다. SAVE 리포트는 날짜와 PDF 버튼이 있는 카드만 담습니다. 본문 상세가256KiB를 넘으면 해당 상세를 생략하여 pending으로 둡니다. 캘린더는 스크롤하지 않고 선택 월과 일치하는 화면 날짜 그룹이나 명시적인 빈 달 안내를 기다린 뒤 한 프레임1MiB 이내로 전송합니다. 다른 달의 오래된 날짜 행이 남아 있으면 calendar_rows_unverified로 실패하며 이전 정상 데이터는 보존합니다. 모든 범위는 partial이며 전체 이력 완료를 뜻하지 않습니다.

PDF 연결은 정해진 시간 동안의 DOM handoff이며 임의의 비동기 웹사이트 내부 동작 전체의 인과관계를 증명하지 않습니다. MAIN 취소 통지는 nonce·소유 탭·현재 작업 증거로 확인합니다. 주소 수신 후라도 다운로드 시작 전에 취소되면 시작하지 않으며, 시작 API 응답을 기다리는 중 취소되면 반환된 해당 다운로드 ID만 취소하고 Native 연결을 건너뜁니다. 오래된 완료 응답은 새 PDF 작업을 소비하거나 정리하지 않습니다.

PDF 앵커 handoff는 표시된 다운로드 버튼을 누른 뒤의 HTMLAnchorElement.prototype.click과 합성 MouseEvent click의 앵커 전용 dispatchEvent를 지원합니다. 전역 EventTarget은 수정하지 않으며, 원래 상속된 메서드는 종료 시 임시 own property를 삭제하여 복원합니다. 숨김·비활성 버튼은 제외하고 일치하는 표시 버튼이 두 개 이상이면 button_unverified로 중단합니다. 도우미가 준비됐지만 후보 주소가 오지 않은 경우는 candidate_missing으로 구분합니다. 이 지원 경로가 실제 사이트의 내부 구현이라고 단정하지 않으며 설치 후 실제 PDF 결과로 확인합니다.

1.0.8은 실제로 표시되고 활성화된 PDF 버튼 한 개만 선택합니다. anchor.click과 anchor.dispatchEvent의 합성 클릭 모두 정확한 버튼/nonce/same-origin blob 조건에서만 연결하며, 원래 상속된 메서드는 해제 때 own property를 제거하여 복원합니다. 가려진 수집 창의 선택 UI가 갱신되지 않을 수 있으므로 전용 창이 다른 창에 완전히 가려지지 않도록 유지해야 합니다.

1.0.10은 보안 확인을 감지하면 Native 저장 요청이 실패해도 사이트 전체를 먼저 중지합니다. 저장된 중지 상태에서는 탭 조회/생성/이동과 후속 수집/PDF를 진행하지 않습니다. 다시 시작만으로 보안 중단을 해제하지 않으며 직접 확인 후 명시적으로 재개해야 합니다. 숨김·최소화 API 수집은 아직 실제 사이트에 연동되지 않았습니다.

## 1.1.0 숨김 API 시험 모드

수집을 중지한 뒤 팝업의 **숨김 API 수집 (시험 중)**을 선택하고 시작합니다. 기존 DOM 모드가 기본값이며 자동 전환하지 않습니다. API 모드는 단일 소유 탭에서 브라우저가 관리하는 로그인 상태로 확인된 GET 요청만 순차 실행합니다. 탭 활성화·창 포커스·스크롤을 하지 않고, 요청 전 2초 간격을 둡니다. Chrome이 켜져 있고 Mac이 깨어 있어야 합니다. AI·AI API key·열린 Codex/Claude 채팅이 필요하지 않습니다.

현재 확인된 계약은 뉴스 목록, 리포트 목록, 커뮤니티 TOP5, 지수 5종의 실시간/정규장 값, 이전 달~+3개월 캘린더 등 **10/20개 항목**입니다. 미확인 인기 순위 10개는 오류/대기로 표시하며 이전 파일을 덮어쓰지 않습니다. 뉴스 본문·새 PDF 자동 저장도 API 모드에서 미지원입니다. 목록은 최신 20개이며 전체 과거 내역 완료를 뜻하지 않습니다. 모든 저장은 partial로 표시합니다. 기존 DOM 모드의 기능은 유지됩니다.

Native가 만료하는 일회 작업과 정확한 요청 주소를 발급하고 응답 주소·상태·JSON 형식·크기·기간·지수 기준을 검증합니다. 인증 헤더/쿠키는 읽거나 내보내지 않습니다. API 데이터는 수집 필드만 투영합니다. 401/403·HTML 보안 화면·리다이렉트는 전체 사이트를 중지합니다. 429는 Retry-After 및 최소 60초 대기를 저장하여 재시작/모드 전환 후에도 지킵니다. 보안 중단은 직접 확인 후 재개해야 해제됩니다.

검증 범위: 임시 프로필·합성 HTTPS의 실제 Chromium에서 window minimized/document hidden, production worker/content의 API 요청, 브라우저 관리 합성 쿠키 전달, 포커스 미변경, 실제 Native 검증/Store 저장을 검사합니다. 실제 SaveTicker 계정의 숨김 운영·새 PDF·장시간·Chrome 재시작·탭 폐기 복구는 미검증입니다. 보안 확인이 반복되면 시작/재개를 누르지 마세요. 사이트 보안 확인 문제를 이 모드가 해결한다고 보장하지 않습니다.


## 1.2.0 API 수집 범위 확대 (시험 모드)

기본 그룹은 로그인된 페이지의 그룹 목록에서 `isDefault` 하나를 확인해 초기화합니다. 그룹 이름은 Native에 전달하지 않고 숫자 ID만 세션 메모리에 둡니다. 인기 순위 10개를 추가해 20개 스트림을 처리하며, 정규장 인기 순위는 서버가 `basis=live`, `session=open`을 명시한 장중 동일 기준에 한해 저장합니다. 장외 정규장 요청 조건은 아직 확인되지 않아 이전 정상 데이터를 보존하고 오류로 표시합니다.

뉴스는 한 번에 최대 2개의 Native 발급 본문만 추가 요청하고 이미 저장된 본문은 재사용합니다. 리포트는 한 번에 최대 1개 상세와 PDF만 처리합니다. PDF 응답은 크기·형식·출처를 확인한 뒤 소유 blob과 반환된 다운로드 ID를 기존 Native ticket에 연결합니다. 중지 이후의 응답이나 다른 출처의 파일은 저장하지 않습니다. 모든 요청 사이에 최소 2초 간격을 두며 인증 실패·보안 확인은 전체 중지, 429는 저장된 대기 시간을 적용합니다.

임시 프로필의 격리된 Chromium에서 최소화·document hidden 상태의 실제 다운로드와 Native PDF 파일 검증이 통과했습니다. 합성 시험은 실제 SaveTicker의 장시간 세션·장외 정규장·보안 확인 통과를 보장하지 않습니다. 설치된 1.1.0의 숨김 운영에서 갱신 중단 구간이 관찰돼 원인 확인 및 새 버전의 실제 계정 검증이 남아 있습니다.

## 1.2.1 정규장 요청 보완

장외 화면에서 확인한 `basis=regular` query를 정규장 인기 순위 5개에 명시합니다. 응답이 regular를 확인하면 정규장 값으로 저장하며, 실시간 값에 regular 이름을 임의로 붙이지 않습니다. session=open은 과거 스냅샷에도 남을 수 있으므로, 정규장 요청에 실시간 응답을 대신 저장하지 않습니다. 장외 계약 미확인이라는1.2.0 제한을 보완하며, 사이트 인증/보안 확인 문제는 여전히 전체 중지 조건입니다. 실제 전체20개 저장 수락은 설치 후 확인해야 합니다.


## 1.2.2 PDF 응답 대기

실제 PDF가 검증 저장됐는데도 20초 응답 제한 때문에 미확인으로 표시되는 경우를 보완합니다. Native의 PDF 저장 응답만 최대90초 기다리며, 다른 Native 요청20초·웹 요청15초·발급 ticket120초 제한과 중지/늦은 응답 보호는 유지합니다. 이 변경은 사이트 보안 재확인 해결을 뜻하지 않습니다.
